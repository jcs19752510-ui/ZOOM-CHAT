## 변경 이력
| 버전 | 날짜 | 내용 |
|---|---|---|
| 0.1 | 2026-10-01 | 최초 작성 |

| 용어 | 쉬운 설명 |
|---|---|
| 방 | 회의가 열리는 공간. 링크를 아는 사람이 들어올 수 있다. 마지막 사람이 나가면 사라진다. |
| 방 ID | 방마다 붙는 길고 추측하기 어려운 번호. 링크 안에 들어 있다. |
| 호스트 | 방을 만든 사람. 방 잠금, 강제 퇴장, 전체 음소거를 할 수 있다. 호스트가 나가면 가장 먼저 들어온 참가자가 이어받는다(승계). |
| 참가자 | 방에 들어와 있는 사람(호스트 포함). |
| 대기실 | 방에 들어가기 전에 카메라·마이크를 확인하는 화면. |
| 닉네임 | 회의에서 보이는 이름. 본인 확인용이 아니다. |
| 세션 토큰 | 입장할 때 서버가 주는 짧은 시간 유효한 확인표. 연결이 끊겼다 돌아왔을 때 같은 자리임을 증명한다. |
| 재접속 유예 | 연결이 끊긴 뒤 자리를 지켜 주는 시간(기본 20초, 제안). |
| 시그널링 | 두 브라우저가 서로를 찾아 연결 방법을 주고받는 과정. 서버가 중간 전달만 하고 영상은 지나가지 않는다. |
| WebRTC | 브라우저끼리 직접 영상·음성을 주고받는 기술. 설치가 필요 없다. |
| mesh | 모든 참가자가 서로 직접 연결하는 방식. 6명 이하에 적합하다. 인원이 늘면 각자 보내야 할 영상이 늘어난다. |
| SFU | 서버가 영상을 받아 나눠 주는 방식. 큰 모임에 적합하다. MVP에서는 만들지 않는다. |
| STUN | 내 공인 주소를 알려 주는 서버. |
| TURN | 직접 연결이 안 될 때 영상을 대신 전달해 주는 서버. 트래픽 비용이 든다. |
| ICE | 두 브라우저가 가능한 연결 경로를 찾는 절차. 실패하면 다시 시작할 수 있다. |
| 발언자 강조 | 말하는 사람의 영상 테두리를 눈에 띄게 하는 기능. |
| 조작 | 입장 성공 기준을 셀 때의 단위: 사용자가 직접 하는 입력·선택·클릭 1회. 링크 클릭 자체는 세지 않고, "닉네임 입력", "권한 허용", "[입장] 누르기"를 각각 1회로 센다. |
| 유예 중 참가자 | 연결이 끊겼지만 자리를 보존 중인 참가자. 정원에는 포함된다. |
| 강퇴 | 호스트가 참가자를 방에서 내보내는 것. 같은 사람이 다시 들어오지 못하게 막는다. |
| 방 잠금 | 새 사람의 입장을 막는 호스트 기능. 이미 있는 사람은 영향이 없다. |
| 전체 음소거 | 호스트가 모든 참가자의 마이크를 한 번에 끄는 기능. 각자 다시 켤 수 있다. |
| KPI | 성공 여부를 숫자로 재는 지표. |
| MoSCoW | 요구의 우선순위 표기(Must/Should/Could/Won't). |
