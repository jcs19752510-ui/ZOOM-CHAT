## 0. 왜 이렇게 하나요
- 폰 브라우저는 **HTTPS 주소에서만 카메라·마이크를 허용**합니다. `http://192.168...` 같은 주소는 막힙니다.
- 그래서 내 컴퓨터에서 앱을 켜고, **HTTPS 임시 주소(터널)**를 만들어 폰에서 엽니다.
- 시험이 끝나면 터널을 닫습니다. 서버를 인터넷에 올리는 "배포"가 아닙니다.

## 1. 준비물
- 컴퓨터(Windows/Mac) 1대: Node.js 22 이상, Git 설치. 켜 둔 채로 시험합니다.
- 스마트폰 2대(iPhone Safari, Android Chrome 각 1대면 이상적).
- 터널 도구 1개. 예: Cloudflare Tunnel(`cloudflared`) 또는 ngrok. 두 도구의 **무료 정책·약관은 미확인**이므로 사용 전 공식 안내를 확인하세요.

## 2. 컴퓨터에서 앱 준비 (한 번만)
```bash
git pull origin PROD
npm ci
npm run build
```
- 터미널 위치는 프로젝트 폴더입니다. 폴더 안에 같은 이름의 폴더를 또 만들지 마세요.

## 3. 터널 먼저 열기 (주소를 먼저 알아야 합니다)
다른 터미널 창에서 실행합니다. 예(Cloudflare):
```bash
cloudflared tunnel --url http://localhost:3001
```
- 화면에 `https://무작위이름.trycloudflare.com` 같은 주소가 나옵니다. 이 주소를 메모합니다.
- 다른 도구라면 "내 컴퓨터 3001번 포트를 HTTPS로 공개"하도록 설정하면 됩니다.

## 4. 서버 켜기 (주소를 환경변수로 알려 줍니다)
비밀값은 시험용으로 새로 만듭니다(예제 값 사용 금지, 운영 모드는 예제 값을 거부합니다).

Mac/Linux:
```bash
export NODE_ENV=production PORT=3001
export SESSION_SECRET="$(openssl rand -base64 48)"
export WEB_DIST=apps/web/dist
export ALLOWED_ORIGINS=https://무작위이름.trycloudflare.com
export TRUST_PROXY=1
npm start
```
Windows PowerShell은 `$env:이름="값"` 형식으로 같은 값을 넣습니다(비밀값은 임의의 긴 문자열 32자 이상).
- `ALLOWED_ORIGINS`는 **주소 하나만, 끝에 `/` 없이** 넣습니다. 틀리면 입장이 거부됩니다.
- 컴퓨터 브라우저에서 `https://무작위이름.trycloudflare.com/healthz`를 열어 `{"status":"ok"}`가 보이면 준비 완료입니다.
- 터널 주소가 바뀌면(다시 열면 바뀝니다) 서버를 껐다가 새 주소로 다시 켭니다.

## 5. 폰 시험 순서
기록은 `docs/05-qa/test-reports/phone-test-YYYYMMDD.md`에 합니다(양식은 `internal-test-guide.md` 3장).

| 순서 | 할 일 | 합격 기준 |
|---|---|---|
| 1 | 폰 A에서 터널 주소를 열고 [방 만들기] → 닉네임 → 권한 허용 → [입장] | 3번 이내 조작, 내 영상이 보인다 |
| 2 | 링크 복사로 폰 B에 보내서 입장 | 두 폰에서 서로 영상·소리가 보이고 들린다 |
| 3 | 폰 A 마이크·카메라 끄기/켜기 | 폰 B 화면에 표시가 즉시 바뀐다 |
| 4 | 채팅에 `<b>안녕</b>` 보내기 | 글자 그대로 보인다 |
| 5 | 폰 세로/가로 회전 | 가로 스크롤 없음, 버튼이 눌린다 |
| 6 | 폰 B를 Wi-Fi→LTE로 바꾸기(가능하면) | 20초 안에 복구, 안 되면 아래 TURN 참고 |
| 7 | 카메라 권한 "차단" 상태로 입장 | 원인과 해결 방법 안내가 보인다 |
| 8 | 화면 잠금 10초 후 해제 | 자리 복구 여부 기록(iPhone은 백그라운드 제약이 있어 안 될 수 있음, 결과를 그대로 기록) |
| 9 | 10분 통화 | 끊김·소리 품질을 점수로 기록 |
| 10 | 호스트가 강퇴 → 같은 폰 재입장 | 재입장 거부 |

## 6. 안 될 때
| 증상 | 원인 후보 | 조치 |
|---|---|---|
| 입장 시 오류, 서버 로그에 origin 거부 | `ALLOWED_ORIGINS`와 주소 불일치 | 주소를 복사해 다시 설정 후 서버 재시작 |
| 카메라 요청이 아예 안 뜸 | HTTPS가 아님 | 터널 주소(https)로 접속했는지 확인 |
| 입장은 되는데 서로 영상이 안 보임 | 서로 다른 통신망에서 직접 연결 실패 | 같은 Wi-Fi에서 먼저 시험. 다른 망 시험은 TURN 서버(coturn)가 필요(`docs/06-ops/runbook.md`, **실제 인터넷 TURN은 미검증**) |
| 접속이 안 됨 | 컴퓨터 절전, 터널 종료 | 컴퓨터 절전 끄기, 터널 창 확인 |

## 7. 안전 수칙 (보안·개인정보)
- 터널 주소는 **아는 사람에게만** 공유하고, 시험이 끝나면 터널과 서버를 끕니다.
- 시험 중 보이는 영상·이름은 개인정보입니다. 화면 캡처를 공유하기 전에 확인하세요.
- 대기실의 "IP 노출 가능성" 안내는 정상 동작입니다.
- `.env`와 비밀값은 커밋하거나 메신저로 보내지 마세요.

## 8. 결과 공유
문제가 생기면 폰 기종·OS·브라우저 버전, 몇 번째 단계에서 어떤 화면이었는지, 스크린샷을 알려 주세요. 재현 테스트를 먼저 만들고 수정합니다.

## 9. 5인 검토
- ① 기획자: 통과. 성공 기준(3번 이내 입장)을 1번 단계에 반영.
- ② 개발자: 통과. 단일 주소 기동과 경로(`/healthz`, `/r/…`)를 클라우드에서 확인. 터널·실제 폰은 미검증.
- ③ 디자이너: 우려. 폰 회전·터치 항목은 실물 확인 전까지 미검증.
- ④ 아키텍트: 우려. 터널 주소가 바뀔 때마다 재기동이 필요(시험용 한계). 다른 망은 TURN 의존.
- ⑤ 보안: 통과. 예제 비밀값 거부, Origin 단일 허용, 시험 후 폐쇄 수칙 포함.
