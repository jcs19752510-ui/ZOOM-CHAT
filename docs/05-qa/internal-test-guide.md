## 변경 이력
| 버전 | 날짜 | 내용 |
|---|---|---|
| 0.1 | 2026-10-01 | 최초 작성. UAT(`uat.md`)·수동 점검(`manual-checks.md`)의 실행 절차 보완 |

자동 테스트(`npm test`, `npm run test:e2e`)는 개발자가 돌린다. 이 문서는 **사람이 직접** 해 보는 내부 시험의 절차다. 시험 시나리오 기준은 `uat.md`, `manual-checks.md`를 따른다. 배포는 하지 않으며 로컬 또는 같은 네트워크에서만 한다.

## 1. 준비 (개발자, 약 10분)
1. `npm ci` → `npm run build` → `.env`를 `.env.example`에서 복사하고 `SESSION_SECRET`, `TURN_SECRET`을 `change-me*`가 아닌 임의의 긴 값으로 바꾼다(운영 모드는 예시값을 거부).
2. `npm run dev` 실행 후 `http://localhost:5173`에서 확인. 다른 기기로 시험하려면 같은 Wi-Fi의 PC 주소로 접속한다. **주의: 카메라는 `localhost` 또는 HTTPS에서만 허용**되므로 다른 기기 시험은 HTTPS 터널(예: 임시 터널 서비스)이 필요하다. 이 경우 `.env`의 허용 Origin에 해당 주소를 넣는다(미확인: 터널 서비스는 아직 선택하지 않음).
3. 테스터에게 방 링크만 전달한다. 설치는 필요 없다.

## 2. 시험 순서 (테스터)
| 순서 | 할 일 | 합격 기준 | 연결 |
|---|---|---|---|
| 1 | 링크를 열고 닉네임 입력 → 권한 허용 → [입장] | 3번 이내 조작으로 입장, 내 영상이 보인다 | UAT-01 |
| 2 | 두 번째 기기·브라우저로 같은 링크 입장 | 서로 영상·소리가 보이고 들린다 | UAT-01 |
| 3 | 마이크/카메라 끄기·켜기, 상대 화면에서 표시 확인 | 상대에게 즉시 반영 | FR-07 |
| 4 | 채팅 보내기(링크, `<b>태그</b>` 포함) | 글자 그대로 표시, 서식이 적용되지 않음 | SEC-07 |
| 5 | 화면공유(PC만) 시작·중지 | 큰 화면 + 썸네일, 중지 시 복귀 | FR-09 |
| 6 | 호스트가 방 잠금 → 새 사람 입장 시도 | 입장 거부 안내 | FR-14 |
| 7 | 호스트가 참가자 강퇴 → 같은 사람 재입장 시도 | 재입장 거부 | FR-15 |
| 8 | 한 기기의 Wi-Fi를 10초 껐다 켜기 | 20초 안에 자리 복구, 안내 문구 이해 가능 | UAT-05 |
| 9 | 카메라 권한을 차단한 채 입장 | 원인과 해결 방법 안내가 보인다 | UAT-03 |
| 10 | 스마트폰(세로)으로 입장 | 가로 스크롤 없음, 버튼 터치 가능 | UAT-02 |
| 11 | 키보드(Tab/Enter)만으로 입장 → 나가기 | 막힘 없이 완주 | NFR-09 |
| 12 | 5~6명이 10분 통화 | 끊김·소리 품질 평가 기록 | UAT-06 |

## 3. 결과 기록 양식
시험마다 아래 한 줄을 `docs/05-qa/test-reports/internal-test-YYYYMMDD.md`에 적는다(파일은 수행 후 새로 만든다).

| 날짜 | 순서 | 기기·브라우저(버전) | 네트워크 | 결과(합격/불합격) | 관찰 내용·스크린샷 |
|---|---|---|---|---|---|

## 4. 결함 기록
불합격이면 `defects.md` 형식으로 `D-nn`을 추가한다: 재현 순서, 기대 결과, 실제 결과, 기기·브라우저, 심각도(보안 > 기능 불능 > 불편). **버그는 재현 테스트를 먼저 만든 뒤 고친다**(프로젝트 규칙).

## 5. 시험 중 지킬 것 (보안·개인정보)
- 테스트 영상·채팅은 서버에 저장되지 않지만, 상대에게는 IP가 노출될 수 있다(대기실 고지 참고). 시험 참가자에게 미리 알린다.
- 실제 회의 내용이나 민감 정보를 쓰지 않는다. 시험 후 `.env`의 임시 비밀값을 폐기한다.

## 6. 5인 검토
- ① 기획자: 통과. 성공 기준(3번 이내 조작)과 엣지 케이스(강퇴, 잠금, 끊김)를 포함했다.
- ② 개발자: 우려. 다른 기기 시험의 HTTPS 터널 방법은 미확인이다.
- ③ 디자이너: 통과. 모바일·키보드·권한 거부 시험을 포함했다.
- ④ 아키텍트: 통과. 단일 서버 로컬 시험 범위로 한정했다.
- ⑤ 보안: 통과. 예시 비밀값 금지, IP 노출 고지, 민감 정보 사용 금지를 명시했다.
