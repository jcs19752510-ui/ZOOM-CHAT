## 1. 로그 (pino, JSON)
| 이벤트 | 필드 | 비고 |
|---|---|---|
| `server listening` | port, env | |
| `room created` | room(앞 6자), rooms(현재 방 수) | |
| `participant joined` | room(앞 6자), size | 닉네임 미기록 |
| `shutting down` | signal | |
| `handler error`, `http error` | event/status, type(오류 이름) | 스택·페이로드 미기록 |

**남기지 않는 것(SEC-10, POL-09)**: 닉네임, IP 원문, 토큰, 비밀번호, SDP, ICE 후보, 채팅 본문. `redact` 설정이 `*.token/password/sdp/candidate/text/nickname`을 가린다. 확인: MC-05, 서버 로그 점검(`security-checklist.md`).

## 2. 지표 (MVP 최소)
| 지표 | 출처 | 목적 |
|---|---|---|
| 동시 방 수 | 로그 `rooms` 필드, `/healthz` 확장은 후보 | 용량(NFR-04) |
| 입장 성공률(KPI-01) | 서버 입장 성공/거부 카운터(코드별) | 품질 |
| 재연결 성공률(KPI-04) | `room:resume` 성공/실패 | 안정성 |
| TURN 사용률(KPI-05) | coturn 통계 또는 클라이언트 보고 | 비용 |
| 프로세스 메모리·CPU | 호스트 모니터링 | 용량 |

현재 구현은 **로그까지**이며 지표 수집기(Prometheus 등)는 넣지 않았다(범위 통제). 필요해지면 `rooms`/`participant` 이벤트 로그를 집계하는 것부터 시작한다(후속 제안).

## 3. 알람 기준 (제안, 배포 후 조정)
| 조건 | 심각도 | 대응 |
|---|---|---|
| `/healthz` 실패 2분 이상 | 높음 | `runbook.md` 재시작 절차 |
| 메모리가 평소의 2배 이상으로 지속 | 중간 | 방·소켓 수 확인, 재시작 |
| 입장 실패(`SERVER_BUSY`) 증가 | 중간 | `MAX_ROOMS` 조정 또는 남용 점검 |
| TURN 트래픽 급증 | 높음 | 남용 점검, 자격증명 TTL 단축, 할당량 조정 |
| 인증서 만료 14일 전 | 중간 | 갱신 |

동시 방/참가자 수, 입장 성공률, 재연결 성공률, 서버 메모리, TURN 대역폭.
