### 1.4 FLOW-03 + FLOW-10 연결 끊김·백그라운드 복귀 [구현 + 신규설계]

```
[SCR-03 회의실, status=live]
  네트워크 단절(소켓 disconnect) ─→ status=reconnecting
       상단: 배지 "재연결 중 · N s"(grace 남은 초) + 노란 배너(role=status) "연결이 끊겨 다시 연결하는 중입니다. 자리는 잠시 유지됩니다."
       타일: 해당 참가자 위에 "재연결 중" 띠
       소켓 재연결 + room:resume 성공 ─→ live 복귀, 토스트 "다시 연결되었습니다"(같은 selfId)
       유예(기본 20초) 초과·토큰 무효 ─→ [expired 화면] "연결이 오래 끊겨 회의에서 나갔습니다" [다시 입장]
  품질 저하(poor) ─→ 배지 "불안정" + 배너 "네트워크가 불안정합니다. 카메라를 끄면 개선될 수 있습니다."

[신규] 앱 전환·화면 잠금 후 복귀(visibilitychange=visible 또는 pageshow)
  t=0   복귀 감지(500ms 안의 중복 이벤트는 1회로 합침)
        로컬 트랙 점검 → 끊긴 카메라/마이크가 있으면 해당 버튼을 "꺼짐" 상태로 바꾸고 warn 토스트(S.background.mediaLost)
  이미 끊김을 알고 있음 ─→ 즉시 재연결 시도, 1초 안에 "재연결 중" 배너·배지(기존 UI 그대로, 복귀가 트리거면 문구만 S.background.returned, F-9)
  조용히 끊김(소켓은 살아 있다고 믿음) ─→ 3초 프로브 → 실패 → 소켓 재연결 → 5초 이내 같은 배너
  프로브 성공 ─→ **아무것도 보이지 않는다**(데스크톱 탭 전환마다 안내가 뜨는 소음을 막기 위한 의도)
  유예 안 복구 → 기존 토스트 / 유예 초과 → expired 화면(본문 뒤에 플랫폼 안내 한 문장 추가, S.background.platformNote)
```

백그라운드 허용 시간은 서버 감지(최대 10초)+유예(20초)=약 20~30초다(03 §4.5, DEC-011). 이 시간은 UI에 숫자로 약속하지 않는다(설정값이고 UAT 전이라 미검증).

```
   └─ 안내 바가 강제로 **펼쳐져** 보이고(이때 [✕]·접기 버튼은 없음) 닫아 둔 상태여도 다시 나타난다(원인일 가능성이 높은 순간이므로)
```

### 1.9 조작 수 예산 검토 (NFR-01: 링크 클릭 후 3번 이내)

| 경로 | 현재 조작(구현) | 신규 UI의 영향 |
|---|---|---|
| 참가자 최소(재방문, 권한 허용 저장) | 입장 1(닉네임 저장값·권한 기억) | 0 |
| 참가자 일반 | ① 닉네임 입력 ② 권한 허용 ③ 회의 입장 = 3 | **0**: 푸터 링크·안내 바는 선택 요소이고 필수 입력·확인 체크박스를 추가하지 않는다. 연령 확인 체크박스는 도입하지 않는다(DEC-010, 4번 조작 소모) |
| 호스트 | ① 닉네임 ② 새 회의 만들기 ③ 권한 허용 ④ 입장(재방문은 ① 생략) | 0. 기존 NFR-01 문구는 참가자 기준이며 호스트는 재방문 3·최초 4다(기존 사실) |
| 자동재생이 막힌 환경 | 입장 후 영상·소리가 멈춤 | **+1(복구 조작)**: 막히지 않으면 0. 막힌 경우 영상이 보이려면 이 탭이 필요하며 대안이 없다. 발생 조건은 브라우저 정책이며 **실기기(Safari) 미검증**(UAT) |
| 인앱 브라우저 | 앱 안 브라우저는 권한이 막힐 수 있음(1단계 R-3, 실기기 미검증) | 안내가 해결책(기본 브라우저로 열기)을 제시한다. 열어서 다시 시도하면 새 흐름의 3조작이며, 이 우회의 조작 수는 NFR-01 측정에서 별도 표기가 필요(UAT-04) |

**화면 위치 영향(구현 스크린샷 판독)**: 360×740 대기실은 전체 높이 868px이고 "회의 입장" 버튼 하단이 y≈690이라 **현재 여유가 약 50px**뿐이다. 안내 바(접힌 상태 약 120px, 제목 2줄+버튼 행으로 **추정**, 미측정)가 위에 들어가면 버튼이 첫 화면 밖으로 밀려 한 번 스크롤이 필요하다. 조작 횟수는 늘지 않으나 **의도적 비용**이다. 인앱으로 판정된 사용자에게만 나타나고, 접힌 기본값·제목 위주 문구·닫기 버튼으로 높이를 줄였으며 구현 후 360×740 스크린샷으로 실측한다(5.9 체크, IT-10 확장 제안). 푸터는 페이지 맨 아래라 입장 버튼 위치에 영향이 없다. 실제 폰의 주소창 때문에 뷰포트는 더 작아 현재도 스크롤이 필요할 수 있다(미검증).

### 2.1 주 화면 [구현]

**SCR-01 랜딩** — 목적: 이름만 정해 방을 만들거나, 받은 링크로 들어간다.
- 구성: 브랜드 텍스트, `h1` "링크 하나로 바로 시작하세요", 부제, 지원 환경 안내(12px). 카드(`bg-surface`): ① 닉네임(라벨+입력+힌트, `autoComplete=nickname`, 마지막 닉네임 자동 채움) ② 체크박스 "비밀번호 설정 (선택)"(44px 행) → 켜면 비밀번호 입력+힌트 ③ 오류(`role=alert`) ④ [새 회의 만들기] ⑤ 구분선 ⑥ "초대 링크가 있나요?" 링크·방 코드 입력+[입장].
- 레이아웃: `md`(768px) 이상은 좌 소개/우 카드(400px) 가로, 미만은 세로.
- 상태: 기본 / 만드는 중(버튼 "만드는 중…"+비활성) / 닉네임 오류(`invalidNickname`) / 비밀번호 길이 오류(`passwordHint`를 오류로 재사용) / 속도 제한(`rateLimited`) / 서버 오류(`state.error.body`) / 링크 형식 오류(`joinInvalid`). 로딩·빈 상태는 해당 없음(초기 화면). 권한 거부는 해당 없음(카메라는 대기실).
- 구현 사실: 입력 오류가 필드와 `aria-describedby`로 연결되지는 않고(힌트만 연결) `role=alert` 문장으로만 전달된다(5.8).

**SCR-02 대기실** — 목적: 입장 전에 내 영상·소리를 확인하고 닉네임으로 들어간다. 카메라 미리보기 우선.
- 구성: 좌(데스크톱) 미리보기(16:9, 거울상, 마이크·카메라 토글 원형 버튼 44px) → 마이크 입력 레벨 미터(`role=meter`) → (문제 시) 권한 안내 블록 → 마이크·카메라 `select` 2개. 우 카드: `h1` "입장 전 확인", (호스트면 "호스트로 입장합니다"), 닉네임(`autoFocus`), (필요 시) 방 비밀번호, IP 노출 고지 상자(`privacy-notice`, UX-09), 오류, [회의 입장], [처음으로], 구분선, [초대 링크 복사].
- 상태:
  - **로딩**: 권한 프롬프트·장치 시작 중 미리보기 자리에 "준비하는 중입니다", [회의 입장] 비활성.
  - **정상**: 영상+레벨 미터.
  - **권한 거부/장치 없음/사용 중/알 수 없음**(SCR-14 인라인): 경고 테두리 블록(`role=alert`, 아이콘+제목+원인과 해결+[다시 확인]). 입장은 막지 않고 장치가 하나도 없으면 버튼 문구가 "장치 없이 입장".
  - **카메라 꺼짐**: "카메라가 꺼져 있습니다" 표시.
  - **오류(입장 시도)**: 비밀번호 오류·시도 초과·닉네임·속도 제한·일반 오류, 입력 아래 `role=alert`. 방 상태성 오류는 화면 전환(1.3).
  - **입장 중**: "입장하는 중…".
- 레이아웃: `md` 이상 좌우(카드 380px), 미만 세로(미리보기가 먼저). 장치 선택은 `sm` 이상 3열 그리드이나 마이크·카메라 2칸만 사용(스피커는 대기실에서 미제공, 회의 중 시트에서 선택).
- 구현 차이: `screen-spec`의 "남은 시도 가능 여부 안내(POL-11)"는 **구현되지 않았다**(서버가 남은 횟수를 주지 않음, 7.1). 구현이 정본이다.

**SCR-03 회의실** — 목적: 서로 보고 말하며, 채팅·참가자 관리·화면공유를 한다.
- 구성(위→아래): 헤더(브랜드, 잠금 아이콘, 연결 배지, [링크 복사 compact], 모바일 [설정]) → (조건부) 재연결 배너 또는 불안정 배너(둘 중 하나, 노란색) → 본문(비디오 그리드 + 데스크톱 우측 340px 패널) → 하단 컨트롤바(마이크, 카메라, 화면공유, 채팅, 참가자 | 나가기) → 토스트 영역 → (조건부) 장치 시트·확인 모달.
- 그리드: 1~6명 자동. 데스크톱 1명 1열, 2~4명 2열, 5~6명 3열. 모바일(<640px) 1~2명 1열, 3~6명 2열. 마지막 줄이 덜 차면 가운데 정렬. 화면공유 중에는 큰 공유 화면+참가자 썸네일 열(데스크톱 우측 192px 폭, 모바일 하단 줄). 내가 공유 중이면 큰 영역에 "내 화면을 공유 중입니다" 카드.
- 상태:
  - **빈 상태(SCR-12)**: 혼자일 때 화면 하단 중앙 카드 "아직 아무도 없어요 / 링크를 복사해서 참가자를 초대해 보세요" + 링크 복사.
  - **연결 문제**: 1.4의 배너·배지·타일 띠.
  - **카메라 꺼짐 타일**: 이니셜 원형 아바타, 접근성 이름 "이름: 카메라 꺼짐".
  - **말하는 중**: 4px 초록 링(색 외에 이름 변화는 없음 — 1.4.1은 "말하는 사람 강조"가 부가 정보라 허용, 5.4).
  - **화면공유 비활성**: 모바일/미지원이면 버튼 `disabled`+`title`·`aria-label`에 사유.
  - **패널 열림**: 데스크톱은 우측 열, 모바일은 **영상 영역 전체를 덮는 오버레이**(컨트롤바는 계속 사용). `screen-spec`의 "바텀시트"가 아니라 오버레이가 구현 정본이다. Esc로 닫힘(모달이 없을 때).
  - **토스트**: 입퇴장, 호스트 변경, 잠금, 재연결, 전체 음소거 알림, 장치·공유 오류(4.5초, 최대 4개).
  - 로딩: 방 입장 전 SCR-11, 회의실 자체의 로딩 화면은 없다(입장 성공 후 렌더).
- 권한 거부: 회의 중 카메라/마이크 켜기 실패는 warn 토스트 `cameraFailed/micFailed`(원인+해결 방법 포함).

**SCR-04 채팅 패널**: 헤더(제목, 닫기 44px), `role=log aria-live=polite` 목록(말풍선, 이름·시각, 링크는 텍스트로 자동 변환·새 탭·`rel=noopener noreferrer`), 입력+보내기(아이콘 버튼), 글자 수 `n/500`.
- 상태: **빈 상태**("첫 메시지를 보내 보세요 / 대화는 서버에 저장되지 않고…"), 전송 중 즉시 입력 비움(실패 시 복원), 오류(500자 초과, 속도 제한, 전송 실패, `role=alert`), 보내기 버튼은 공백이면 비활성. 500자 초과 시 카운터가 `danger-text`. 패널이 닫혀 있을 때 새 메시지는 컨트롤바 배지(시각)로만 알려진다(G-15).

**SCR-05 참가자 패널**: 헤더 "참가자 N명", (호스트만) 호스트 도구 영역 [방 잠그기/해제](`aria-pressed`)·[전체 음소거], 목록(이니셜, 이름, (나), 왕관, 재연결 중 라벨, 화면공유·마이크·카메라 아이콘, 호스트에겐 [내보내기] 44px). 상태: 호스트 아님(도구 숨김; 권한은 서버가 판단), 재연결 중 라벨. 빈 상태는 없음(본인이 항상 포함).

**SCR-06 장치 설정 시트**: 모달 다이얼로그(`aria-modal`, 제목, 닫기). 마이크·카메라·스피커 `select`. 상태: 목록 없음("선택 가능한 장치가 없습니다", 비활성), 스피커 미지원("이 브라우저는 스피커 선택을 지원하지 않습니다…"), 모바일은 하단 시트·데스크톱은 가운데. 장치 변경 중에도 통화는 유지.

**SCR-07 확인 모달**: 나가기·내보내기·전체 음소거 3종. 기본 포커스 [취소], Esc로 닫힘, Tab이 창 안에서 순환, 닫히면 이전 포커스 복원. 위험 동작(나가기·내보내기)은 `btn-danger`.

### 2.3 신규 화면·상태 [신규설계]

#### 2.3.1 법률 링크 푸터(`LegalFooter`) — SCR-01·02 확장 (POL-17·19·20)

- **목적**: 입장 전에 처리방침·약관·문의·신고에 접근한다. 한 번 클릭.
- **위치**: 랜딩·대기실의 `<footer>`(맨 아래, 본문 뒤, 입장 버튼 위치에 영향 없음). 두 페이지는 지금 루트가 `<main className="min-h-full ...">` 하나뿐이라, 푸터를 추가하려면 루트를 `flex min-h-full flex-col`로 감싸고 `main`을 `flex-1`, `footer`를 `shrink-0`으로 둔다. 그렇지 않으면 1280×800에서 푸터 높이만큼 새 세로 스크롤이 생긴다(F-7).
- **구성**: `<nav aria-label="법적 고지와 문의">`에 링크 3개 "개인정보 처리방침 · 이용약관 · 문의·신고". 각 링크 `min-h-touch`(44px) `px-2`, 12px `text-muted`, 항상 밑줄. `target="_blank" rel="noopener noreferrer"`, 접근 가능한 이름은 `"{이름} (새 탭에서 열림)"`.
- **상태**: 링크만 있으므로 로딩·오류·빈 상태 없음. 360px에서 한 줄에 들어가며(약 290px) 더 좁으면 줄바꿈.

- **약관(SCR-24)**: 03이 섹션 id를 정하지 않았다(처리방침만 필수 id). 약관은 `S.legal.terms.sections`를 쓰며 **연령 문구(만 14세 이상)**와 서비스 제한(호스트 권한, 신고·종료 가능성)을 포함하는 것은 unit-15·법률 검토 몫이다(POL-20). 입장 흐름에 연령 확인 UI는 두지 않는다(1.9).

- **문서 간 이동**: 같은 탭에서 `history.pushState`. 이동 후 `document.title`을 `"{문서 제목} · MeetLite"`로 바꾸고(페이지를 떠나면 "MeetLite"로 복원) `h1`로 포커스를 옮긴다(`tabindex=-1`). 목차·앵커는 `#id` 해시이며 `popstate`로 `useRoute`가 `pathname`만 다시 읽으므로 화면이 바뀌지 않는다(구현 시 확인, 미검증).

#### 2.3.3 SCR-25 문의·신고 (POL-19)

처리방침과 같은 틀. 본문 구성(문구는 unit-15, 이 단계는 구성·사실 근거):

| 순서 | 제목 초안 | 내용(사실 근거) |
|---|---|---|
| 1 | 신고·문의 연락처 | 슬롯 `contact`. 첫 섹션이므로 **미정이면 강조형(경고 테두리를 굵게, 아이콘 크게) 슬롯**으로 보여 이 페이지의 핵심 요소가 비어 있음을 숨기지 않는다 |
| 2 | 신고할 때 알려 주세요 | 회의 링크(주소), 일시, 어떤 문제인지. **방 비밀번호는 보내지 마세요**(링크는 방을 특정하기 위한 것) |

| 5 | 처리 | "접수한 내용을 확인한 뒤 필요한 조치를 합니다. 처리 기한은 운영자가 정해 안내합니다(미정)." — **기한 수치는 03에 데이터가 없어 약속하지 않는다**(운영자 결정, 질문 Q-U1) |

폼은 만들지 않는다(서버 측 신고 접수는 범위 밖, A-19). 수사기관 요청 응대는 사용자 화면에 두지 않고 runbook 몫이다.

#### 2.3.4 SCR-26 인앱 브라우저 안내(`InAppNotice`) (UX-13)

- **목적**: 앱 안 브라우저에서 카메라·마이크가 막히기 전에 기본 브라우저로 열도록 안내. **입장을 절대 막지 않는다**(오탐 안전).
- **표시 위치**: SCR-01·SCR-02(최상단, `main` 앞)와 SCR-20(`StateScreen` 위, 두 요소를 세로로 쌓는 래퍼 필요). 감지는 `detectInApp(navigator.userAgent).inApp`(순수 함수, 03 §4.5). **인앱이 아니면 렌더링하지 않는다(`null`)**.
- **와이어프레임**(접힘 기본은 제목과 버튼만, 요약은 펼쳤을 때):

```
접힌 상태(기본)  360px                       펼친 상태
┌────────────────────────────────────┐     ┌────────────────────────────────────┐
│ ⚠ 앱 안의 브라우저로 열었다면          │     │ ⚠ 앱 안의 브라우저로 열었다면          │
│   카메라가 막힐 수 있어요             │     │   카메라가 막힐 수 있어요             │
│ [링크 복사] [방법 보기 ▾]        [✕]  │     │ [링크 복사] [방법 접기 ▴]        [✕]  │
└────────────────────────────────────┘     │ Chrome이나 Safari 같은 기본 브라우저에서 │
   각 버튼 44px 이상, 약 120px(추정)           │ 여는 것을 권장합니다.                   │
                                             │ 1. 화면의 메뉴(⋮ 또는 공유 아이콘)에서 … │
                                             │ 2. 메뉴에 없으면 "링크 복사"를 누른 뒤 … │
                                             │ 이 브라우저에서도 계속 진행할 수 있습니다. │
                                             └────────────────────────────────────┘
```

- **상태 표**:

  | 상태 | 조건 | 표시 |
  |---|---|---|
  | 숨김 | 인앱 아님 / 사용자가 [✕] (같은 실행 동안, 메모리) | 렌더링 없음 |
  | 접힘(기본) | 인앱 감지, 닫지 않음 | 제목+3버튼 |
  | 펼침 | [방법 보기] | + 요약·번호 단계·계속 가능 문장, `aria-expanded=true` |
  | 강제 펼침 | SCR-02에서 권한 실패(`mediaProblem`) 또는 SCR-20 | 닫음 상태를 무시하고 항상 펼쳐 표시, **[✕]와 접기 버튼은 두지 않는다**(원인 안내이므로). SCR-02는 기존 권한 안내 블록(`role=alert`)에 한 줄 추가(`S.inApp.permissionExtra`)해 **한 번에 읽히게** 한다. 권한 문제가 풀리면 직전 상태(숨김 또는 접힘)로 돌아간다 |
  | 복사 성공/실패 | 링크 복사 결과 | 기존 `CopyLink` 동작(성공: 버튼 문구 변경, 실패: 안내+선택 가능한 입력창 `role=status`) |

  로딩 상태는 없다(UA는 동기 판정). 빈 상태·권한 상태는 위 표의 숨김·강제 펼침이 해당한다.
- **복사 대상**: SCR-02·SCR-20은 초대 링크(`/r/:id`), **SCR-01은 사이트 주소(`origin`)**. 현재 `CopyLink`는 `roomId`만 받으므로 확장이 필요하다(F-1).
- **접근성**: `aside`(보조 랜드마크) `aria-labelledby`=제목. 라이브 영역이 아니다(로드 시 자동 낭독으로 입력을 방해하지 않음, 포커스 이동 없음, 닉네임 `autoFocus` 유지). 접기 버튼 `aria-expanded`+`aria-controls`. 닫기 버튼 이름 "안내 닫기"이고 닫으면 **포커스를 닉네임 입력으로 옮긴다**(요소가 사라져 포커스를 잃지 않게). Esc로 닫지 않는다(모달이 아님). DOM상 `main` 앞이라 `autoFocus`가 없는 랜딩에서는 첫 Tab 3번이 이 버튼들이다(수용).
- **하지 않는 것**: 앱 고유 스킴으로 외부 브라우저를 자동으로 여는 딥링크(검증 불가), 앱 이름별 맞춤 문구(`perApp`, 메뉴 이름을 확인하지 못함). 문구의 메뉴 이름은 **실기기 확인 전 초안**이다(UAT-04 미수행).

#### 2.3.5 SCR-27 자동재생 탭 재생 배너 (UX-15)

- **목적**: 브라우저가 원격 영상·소리 재생을 막았을 때 한 번의 탭으로 푼다.
- **위치**: 회의실 헤더와 연결 상태 배너 **아래**, 본문(`flex ... gap-2 p-2` 영역) 위(DOM 순서도 동일). 데스크톱·모바일 모두 한 줄 띠(모바일은 줄바꿈 허용, 버튼은 아래 정렬). 연결 배너와 동시에 뜨면 위에서 아래로 연결 배너 → 이 배너.

```
┌──────────────────────────────────────────────────┐
│ ▶ 일부 참가자의 영상이나 소리가 브라우저 설정 때문에    │
│   멈춰 있습니다.                  [ 탭하여 재생 ]     │
└──────────────────────────────────────────────────┘
```

- **구성**: `role=status`, 배경 `raised`, 글자 `text`(대비 12.3:1), 버튼 `btn-primary`(흰 글자/accent 5.3:1, 높이 44px 이상). 타일마다 버튼을 두지 않고 **방 단위 1개**(5명이면 5번 탭이 되고, 카메라가 꺼진 참가자의 숨은 `<video>`도 소리를 재생하므로 타일 UI로는 소리가 안 나는 이유를 보일 수 없다, 03 §4.5).
- **상태**: 숨김(막힌 요소 0) / 표시(≥1) / 재시도 후 일부 남음(배너 유지+warn 토스트 `stillBlocked`) / 성공(배너 제거+info 토스트 `started`). `NotAllowedError` 외의 `play()` 실패(`AbortError` 등)는 배너를 띄우지 않는다.
- **포커스**: 버튼을 활성화한 뒤 배너가 사라지면 포커스가 `body`로 떨어지므로 **회의 화면 영역(`main`, `tabindex=-1`)으로 옮긴다**. 부분 실패면 포커스를 버튼에 둔다.
- **구현 후보(미검증)**: [회의 입장] 클릭 제스처 안에서 재생 권한을 미리 얻는 방법이 있으면 탭 자체를 없앨 수 있다. 브라우저 정책 의존이라 실기기 확인 전에는 효과를 단정하지 않는다(unit-17이 시험).

#### 2.3.7 SCR-19 변형: 운영자 종료 (POL-19)

## 5. 접근성 기준

목표는 **WCAG 2.2 AA**(NFR-09, UX-10, UX-11). 자동 검증은 키보드 도달(IT-11), 접근 가능한 이름(IT-12), aria-live(IT-28), reduced-motion(IT-27), 색 대비(TC-214~217)까지이며 **axe 같은 전용 도구와 실제 스크린 리더는 쓰지 못했다**(UAT-07 미수행).

### 5.1 키보드 내비게이션

- 모든 기능이 키보드로 가능해야 한다(입장~퇴장은 IT-11 자동 검증). 탭 순서는 DOM 순서이며 시각 순서와 같다(CSS 순서 재배치 금지).
- 대기실은 `autoFocus`로 첫 포커스가 닉네임 입력에 있고, 이후 Tab은 DOM 순서(입장·처음으로·링크 복사)를 따른다. 신규 안내 바는 DOM상 앞이지만 `autoFocus`를 유지하므로 입력을 방해하지 않으며, 푸터는 맨 마지막이다. 랜딩은 `autoFocus`가 없어 안내 바가 있으면 첫 Tab 3번이 안내 바 버튼이다(수용).
- 모달(`ConfirmModal`)은 Tab 순환·Esc·포커스 복원을 하며, 시트(`DeviceSheet`)는 현재 순환이 없다(G-2, 개선 대상).
- 패널(채팅·참가자)은 Esc로 닫힌다. 열 때 포커스 이동·닫을 때 복원은 없다(G-3).
- 신규: 법률 페이지의 목차 링크는 앵커 이동, 문서 전환 후 `h1`로 포커스. 안내 바 버튼 3개는 Enter·Space, 닫으면 닉네임 입력으로 포커스. 자동재생 버튼은 활성화 후 포커스를 `main`(회의 화면)으로 이동.

### 5.2 포커스 표시와 가림(2.4.7, 2.4.11)

전역 2px `focus` 링(오프셋 2px)은 `bg`·`surface`·`raised` 위에서 6.6~8.6:1(통과). 고정 요소가 초점을 가리는지는 **미검증**이다: 토스트 컨테이너는 `top-16`에 고정되고 `pointer-events-none`이지만 토스트 본체는 `pointer-events-auto`라 4.5초 동안 헤더 아래 영역을 시각적으로 덮고 클릭을 받는다. 모바일 패널 오버레이는 하단 컨트롤바를 가리지 않는다. 오버레이 아래 `main`의 요소(예: 혼자 있을 때 카드의 [링크 복사])는 가려진 채 초점을 받을 수 있다(G-3).

### 5.3 스크린 리더·라이브 영역

### 5.4 색과 대비

3.2 표 기준. 색만으로 의미를 전달하지 않는다(1.4.1): 연결·마이크·호스트는 아이콘+글자, 리본·미정 상자는 아이콘+문장, 링크는 밑줄. **알려진 예외·미달 후보**: 입력 테두리(G-1), 말하는 사람 링(보조 정보라 허용), 영상 위 글자(미검증).

### 5.5 터치·포인터(2.5.8)

터치 타깃 44px 이상(프로젝트 기준, WCAG 2.2 AA의 24px보다 엄격). 컨트롤바 장치 칩은 데스크톱 전용이며 너비 28px(높이 44px)로 예외(IT-10이 별도 허용). 신규: 푸터 링크 높이 44px, 안내 바 버튼 44px, 자동재생 버튼 44px, 슬롯 재시도 44px. 드래그 필요 동작 없음(2.5.7).

### 5.6 모션(2.3.3, UX-11)

전역 규칙으로 애니메이션·전환을 사실상 끈다(IT-27). 신규 UI에는 애니메이션이 없다(안내 바 펼침·배너 등장은 즉시 표시). 깜빡임 요소 없음.

### 5.7 문구·읽기(3.1, 3.3)

`lang=ko`, 오류는 원인+해결 방법(3.3.1·3.3.3). 법률 본문은 16px, 줄 길이 720px 이하. 약어·전문 용어(STUN/TURN)는 처리방침에서 한 줄 설명을 붙인다(unit-15). 닉네임 저장으로 재입력을 줄인다(3.3.7). 방 비밀번호 입력은 붙여넣기를 막지 않으나 `autoComplete="off"`라 비밀번호 관리자 지원은 약하다(3.3.8, 영향 낮음, 미검증).

### 7.4 정합성 판정

- 모든 신규·기존 핵심 플로우(1.2~1.8)가 03의 REST·소켓·클라이언트 상태로 충족된다. **03에 없는 데이터를 요구하는 화면은 없다**(처리 기한·종료 사유·남은 시도 횟수는 표시하지 않는 것으로 처리).
- 03과 어긋나는 보완 요청 F-1~F-3·F-7·F-9와 확장 F-4, 웨이브 주의 F-8은 추가·보완이며 차단이 아니다. F-5는 선택 제안, F-6은 기존 결함.
- 미검증 목록: 스크린 리더 실사용, 실기기(iOS Safari 입력 확대·인앱·자동재생), 비-Chromium, 320px 리플로우, 영상 위 글자 대비, 안내 바 실제 높이, 자동 TC 재실행(셸 없음).

- ① 기획자 [통과]: 신규 UX/POL 요구(UX-13~15, POL-17·19·20)의 화면·상태·문구를 모두 정했고 조작 수 예산(1.9)에서 필수 조작 +0을 확인했다. 자동재생 차단 시 +1은 불가피한 복구 단계로 명시했다. 법률 문구 확정은 사용자·법률 검토 몫.
- ② 개발자 [우려]: 파일 소유 공백(F-1 `CopyLink.tsx`)·unit-0 범위 정정(F-7)·문구 키 확장(F-2·F-3)·상태 필드(F-9)는 3단계 반영이 필요하다. 이 단계는 셸이 없어 자동 테스트·`check-docs`를 실행하지 못했다.
- ③ 디자이너 [우려]: 입력 테두리 대비 미달 후보(G-1)와 포커스·알림·입력 크기 공백(G-2~G-4, G-15, G-16)은 기존 구현의 결함 후보다. 신규 UI는 기존 토큰만 쓰며 대비를 수기로 확인했으나 스크린 리더·실기기·영상 위 글자·안내 바 실제 높이는 미검증.
- ④ 아키텍트 [통과]: 신규 화면이 03의 데이터·이벤트 범위 안에 있고 새 저장소·API·의존성을 요구하지 않는다. 인앱 안내 닫음 상태는 메모리 변수.
- ⑤ 보안 [통과]: 법률 본문·슬롯은 텍스트 노드로만 렌더링(XSS 경로 없음), 외부 링크 `rel=noopener noreferrer`, 신고 폼이 없어 입력 수집 표면이 늘지 않는다. 신고 안내에 방 비밀번호를 보내지 말라고 명시. 운영자 종료 화면은 사유를 노출하지 않는다.
