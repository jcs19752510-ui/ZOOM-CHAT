값은 모두 서버 설정값(환경변수 → `config.ts`)이다. "제안"은 승인 시 확정한다. 정책이 바뀌면 같은 커밋에서 PRD, 화면 정의서, TC를 갱신한다.

## POL-01 방 정원
- 방당 최대 참가자 수는 `MAX_PARTICIPANTS`(기본 6). 호스트 포함.
- 정원에는 **재접속 유예 중인 참가자도 포함**한다(자리 보존). 정원이 차면 신규 입장은 "방이 가득 찼습니다"로 거부한다.
- 정원 확인과 자리 배정은 서버가 원자적으로 처리한다(동시 입장 경쟁에서 정원 초과 금지).
- 연결: FR-07, FR-06, NFR-04

## POL-02 방 수명
- 마지막 참가자가 나가면 방을 **즉시 삭제**한다. 단 재접속 유예 중인 참가자가 있으면 유예 종료 시 삭제한다.
- 생성 후 아무도 입장하지 않으면 `ROOM_EMPTY_TTL_MIN`(기본 10분) 뒤 삭제한다.
- 삭제된 방의 링크는 "없는 방"으로 응답한다. 방 ID는 재사용하지 않는다(128비트 난수).
- 삭제와 입장은 서버가 직렬 처리한다.
- 연결: FR-18, FR-21, NFR-04, SEC-01

## POL-03 방 잠금
- 호스트만 잠금/해제할 수 있다. 잠긴 방은 **신규 입장**을 거부한다("방이 잠겨 있습니다").
- 기존 참가자와 유예 중 재접속(유효한 세션 토큰)은 허용한다.
- 호스트 승계 시 잠금 상태를 유지한다.
- 연결: FR-14, SEC-05

## POL-04 닉네임 규칙
| 항목 | 규칙 |
|---|---|
| 길이 | 1~20자(유니코드 NFC 정규화 후 코드포인트 기준), 앞뒤 공백 제거, 연속 공백은 하나로 |
| 허용 문자 | 한글(완성형), 영문, 숫자, 공백, `_` `-` `.` |
| 금지 | 제어문자, 제로폭 문자, 방향 제어 문자, 이모지, 그 외 기호 |
| 중복 | 같은 방에서 대소문자·정규화 후 같으면 나중 입장자에게 ` (2)`, ` (3)`을 붙인다. 번호가 붙은 최종 표시명은 최대 24자 |
| 성격 | 표시용이며 신원 보증이 아니다. 같은 브라우저의 다른 탭은 별개 참가자 |
- 연결: FR-01, FR-03, SEC-06, A-09, A-11

## POL-05 호스트 권한과 승계
- 호스트는 방 생성자다. 호스트만 할 수 있는 일: 방 잠금/해제, 강제 퇴장, 전체 음소거. 권한 판단은 **항상 서버 상태**로 한다.
- 호스트가 나가거나 끊기면 `RECONNECT_GRACE_SEC`(기본 20, 제안) 동안 승계를 보류한다. 경과하면 **접속 중인 참가자 중 입장 순번이 가장 앞선 사람**이 호스트가 된다. 모두에게 알림을 보낸다.
- 유예 안에 원 호스트가 복귀하면 호스트를 유지한다. 승계가 끝난 뒤 복귀하면 일반 참가자다.
- 호스트가 자신을 강퇴할 수 없다. 호스트 양도 기능은 MVP에 없다(`roadmap.md` 후보).
- 전체 음소거: 호스트를 제외한 접속 중 참가자의 마이크를 끈다(**끄기만 가능**). 각자 다시 켤 수 있다. 일회성 동작이며 이후 입장자에게는 적용되지 않는다.
- 연결: FR-14, FR-15, FR-16, FR-17, SEC-05

## POL-06 강제 퇴장과 재입장 차단
- 강퇴 대상은 즉시 연결이 끊기고 세션 토큰이 무효가 된다. 강퇴 안내 화면을 본다.
- 재입장 차단 키: **세션 + 네트워크 식별자의 단방향 해시**. 방별 차단 목록은 서버 메모리에만 두며 방 삭제 시 함께 사라진다(A-05, 사용자 승인 필요).
- 한계: 다른 네트워크로 옮기면 우회할 수 있다. 보완 수단은 방 잠금과 비밀번호다. 이 한계를 사용자 문서에 명시한다.
- 호스트 승계 후에도 차단 목록은 유지한다.
- 연결: FR-15, SEC-05, A-05

## POL-07 채팅 규칙
- 메시지 1~500자, 앞뒤 공백 제거, 빈 메시지 거부. 서버가 제어문자를 제거하고 길이를 다시 검증한다.
- **서버에 저장하지 않는다.** 방에 있는 참가자에게만 릴레이하며, 입장 이전 대화는 볼 수 없다.
- 화면에는 텍스트로만 표시한다. `http://`, `https://` 링크만 클릭 가능하며 새 탭에서 `rel="noopener noreferrer"`로 연다.
- 전송 속도 제한 초과 시 전송이 거부되고 안내가 표시된다(수치는 0-C `api-spec.md`).
- 연결: FR-11, SEC-04, SEC-06, SEC-07

## POL-08 오류와 연결 끊김 처리
| 상황 | 처리 |
|---|---|
| 일시적 네트워크 단절 | 자동 재연결 시도(백오프). `RECONNECT_GRACE_SEC` 안에 세션 토큰으로 같은 자리 복구, 상태 표시는 "재연결 중" |
| 유예 초과 | 참가자 퇴장 처리. 클라이언트는 "연결이 오래 끊겨 회의에서 나갔습니다. 다시 입장해 주세요" 안내 |
| 명시적 나가기·탭 닫기 신호 | 유예 없이 즉시 퇴장 |
| 미디어(P2P) 연결 실패 | ICE 재시작 후 실패 시 해당 참가자 타일에 오류 상태와 해결 방법 표시. 전체 연결은 유지 |
| 서버 재시작/방 소멸 | 재접속 시 방이 없음을 확인하면 "서비스가 재시작되어 회의가 종료되었습니다" 안내와 새 방 만들기 제공 |
| 위조·만료 토큰 | 복구 거부, 새 입장 필요. 오류 응답에 내부 정보 미포함 |
- 연결: FR-19, FR-20, FR-21, NFR-03, NFR-06, UX-03, SEC-03

## POL-09 데이터 보존
- 서버는 영상, 음성, 채팅 본문, SDP/ICE를 **저장하지 않는다**. 방 상태(참가자 목록, 호스트, 잠금)는 메모리에만 있고 방 삭제 시 소멸한다.
- 서버 로그에는 방 ID 일부(앞 일부만), 이벤트 종류·결과·오류 코드, 집계 수치만 남긴다. 닉네임, IP 원문, 토큰, 비밀번호, SDP, 채팅은 기록하지 않는다. (보존 기간은 0-D `privacy.md`에서 확정)
- 연결: SEC-10, 0-D `privacy.md`

## POL-10 비정상 이용 대응
- 단계: ① 이벤트 거부와 안내 → ② 반복 위반 시 해당 연결 종료 → ③ 같은 IP+방 조합 일정 시간 입장 차단.
- 방 생성·입장·채팅·시그널링 속도 제한과 값은 0-C `api-spec.md`에 둔다.
- 사용자 신고·문의 창구는 **미확인**(운영자 연락처 결정 필요, 확인 목록 U-03).
- 연결: SEC-06

## POL-11 방 비밀번호와 입장 시도 제한
- 비밀번호는 선택이며 4~32자(A-06, 제안). 서버는 해시로만 보관한다. 비밀번호는 URL에 넣지 않는다.
- 틀린 시도가 5회/10분(IP+방 기준, 제안)을 넘으면 10분간 해당 조합의 입장 시도를 거부한다. 응답은 방 존재 여부 외 정보를 주지 않는다.
- 유효한 세션 토큰으로 재접속할 때는 비밀번호를 다시 묻지 않는다.
- 연결: FR-05, SEC-02, A-06

## POL-12 화면공유
- 방당 동시 1명, 먼저 시작한 사람이 우선이다(A-04). 이미 공유 중이면 다른 참가자의 시작은 거부하고 "OO님이 공유 중입니다"를 안내한다.
- 공유자가 나가거나 연결이 끊기면 공유는 즉시 종료되고 그리드로 복귀한다. 호스트가 타인의 공유를 중지시키는 기능은 MVP에 없다(강퇴로 대응).
- 모바일 브라우저는 화면공유 미지원이며 버튼을 비활성화하고 이유를 안내한다.
- 연결: FR-12, UX-06

## POL-13 호스트 입장 전 대기
- 방 생성자가 입장하기 전에는 다른 참가자가 방에 참가자로 추가되지 않는다. 대기 화면을 보여 주고 호스트가 입장하면 자동으로 진행한다(A-03, 사용자 승인 필요).
- 목적: 링크가 먼저 새어도 생성자가 아닌 사람이 호스트가 되지 않게 한다.
- 호스트 대기 중인 사람은 정원에 포함하지 않는다. 대기 시간은 `ROOM_EMPTY_TTL_MIN`에 포함된다(그 안에 호스트가 입장하지 않으면 방 삭제).
- 연결: FR-23, SEC-05

## POL-14 지원 환경과 제약
- 지원: Chrome/Edge/Firefox/Safari 최신 2개 버전, iOS Safari 포함.
- 제약 문서화(확인 방법은 호환성 매트릭스): 모바일 화면공유 미지원, iOS 백그라운드 전환 시 미디어 중단 가능, 자동재생 정책으로 첫 상호작용 후 소리 재생.
- 지원 불가 환경(WebRTC 미지원 등)은 안내 화면을 보여 준다. 정확한 API 지원 범위는 **미확인**(A-08).
- 연결: NFR-05, RISK-03

## POL-15 서버 보호 한도
- IP당 동시 연결 수, 서버 전체 방 수(`MAX_ROOMS`, 제안 100), 이벤트별 속도 제한을 둔다. 한도 초과 시 새 방 생성/연결을 거부하고 안내한다.
- NAT 뒤 여러 사람이 같은 IP를 쓸 수 있으므로 IP당 한도는 방 정원을 고려한 값으로 0-C에서 정한다.
- 연결: FR-01, SEC-06, NFR-04

## POL-16 개인정보 고지
- 대기실에 "영상 통화 연결 과정에서 다른 참가자에게 네트워크 정보(IP 등)가 보일 수 있습니다" 안내를 표시한다. 문구와 상세는 0-B `content-guide.md`, 0-D `privacy.md`.
- 연결: UX-09, SEC-10
