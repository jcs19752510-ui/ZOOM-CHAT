## 2. 테스트 범위 및 제외 범위
- 범위(In-Scope): (a) 사용자 시나리오 전수(링크→입장→영상→채팅→화면공유→호스트 도구→재연결→호스트 승계→나가기, 호스트 이탈·빈 방·재입장 엣지) (b) 크로스모듈: 서버 SIGTERM 재시작, 운영자 방 폐쇄, TURN(coturn) 경유+재시작, 서버 상한(방 수·IP당 연결), 보안 헤더·로그 개인정보 (c) 성능 스모크: 첫 영상까지·6명 mesh·서버 RSS/CPU·`load-smoke` 30/100방 (d) 요구 59건(FR 23·NFR 13·UX 12·SEC 11)·POL 16건의 시험 연결 확인 (e) KPI 계측 가능성·UAT 구분 (f) 전체 회귀: lint·typecheck·단위·check-docs·audit·E2E
- 제외 범위 및 사유: 실기기(iPhone Safari·Android·인앱 브라우저)·Firefox/Safari/Edge — 이 환경에 없음(UAT-02·04·05·07, 사용자 수행) / 실제 인터넷·NAT·LTE 망 품질, 20분 이상 장시간(IT-29 soak은 `SOAK_MINUTES` 없이 skip) / 도커 이미지 빌드·compose·GitHub Actions 실행 / 법률 검토·실제 운영자 연락처 / 배포(규칙 E, 10~12단계) / 제품 코드 수정(이 단계 금지 — 결함은 `test.fail`로 재현만)
- **브라우저 MCP(Playwright/Chrome)는 연결되어 있지 않다(DEC-001).** 대신 저장소의 npm Playwright(사전 설치 Chromium, headless, `--use-fake-device-for-media-stream`)를 썼다. **사람이 실제 화면을 눈으로 본 확인이 아니다** — 화면 텍스트·역할·요소 상태·실제 `video.videoWidth`로 판정했고, 시각 품질(깨짐·가독성)은 IT-10 스크린샷 시험(기존)에 의존한다.

## 3. 테스트 환경
- 실행 환경: Linux 6.18, **4코어·RAM 16GB**, Node 22.22.0, Chromium(사전 설치, headless), coturn 4.6.1(`/usr/bin/turnserver`), 서버는 `node apps/server/dist/index.js` + `NODE_ENV=production` + 웹 `apps/web/dist`(`npm run build`). 모든 시험이 루프백(127.0.0.1)이라 **네트워크 지연·손실·NAT는 없다**. 서버와 브라우저 6개가 같은 4코어 머신을 공유한다(서버 CPU 수치는 이 조건)
- 테스트 데이터: 시험 중 생성(ASCII 닉네임, 랜덤 방 ID·SESSION_SECRET). 한글 문구는 시험 코드에 하드코딩하지 않고 `strings.ts`의 `S`로 참조(TC-213 유지)
- 전제 조건: 7단계 6건 결과 존재, 5~7단계 완료(커밋 76c8536), `npm ci`·`npm run build` 완료
- 시험 방식 핵심: `e2e/system.spec.ts`(신규 IT-90~IT-102)가 운영 빌드 프로세스를 `spawn`해 stdout 로그·`/proc/<pid>` 자원·SIGTERM을 직접 다룬다. 웹소켓은 Playwright `routeWebSocket`으로 가로채 프레임 기록·단절을 유도한다(서버가 실제로 내려가는 IT-93·100은 가로채기 없이 브라우저 본래 동작)
