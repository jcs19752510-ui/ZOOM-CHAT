## 2. 결과 (이 샌드박스, 2026-10-01)
**시그널링 부하 스모크**: 소켓마다 offer 1개(약 5.4KB)와 ICE 후보 12개를 같은 방 모든 사람에게 순차 전송, 채팅 1개. 소켓끼리는 동시.
| 구성 | 소켓 | 신호 요청 | 소요 | ack 지연 p50 / p95 / p99 / max | 오류 | 서버 메모리 | 서버 CPU |
|---|---|---|---|---|---|---|---|
| 30방 × 6명 | 180 | 11,880 | 0.6초(약 1.8만 건/초) | 7 / 21 / 32 / 42 ms | 0 | 80→117 MB | 1.1초 |
| 100방 × 6명 | 600 | 39,600 | 1.7초(약 2.4만 건/초) | 21 / 43 / 57 / 85 ms | 0 | 83→130 MB | 2.8초 |
모두 나가면(재접속 유예 1초 설정) 방이 정리됨을 확인했다. 서버 상한은 `MAX_ROOMS=100`(설정값)이다.

**첫 영상까지**: 로컬 루프백에서 5회 측정 432–487ms. 이 값은 **실제 인터넷·NAT 환경의 값이 아니다**(KPI-03 실측은 UAT-06/운영 관측).

**6명 mesh**: 6명 전원이 서로 5개씩 비디오+오디오를 받는 데 약 5초(브라우저 6개를 한 프로세스에서 띄운 환경). 6명 방에서 모든 카메라 송신이 `maxBitrate 400,000`, `scaleResolutionDownBy 2`로 설정됨을 확인.

## 3. mesh 한계와 SFU 전환 기준
- 6명 업링크: 5개 스트림 × 400kbps ≈ **2Mbps**(상한 기준 계산, TC-211). 화면공유 중에는 최대 1.5Mbps가 더해진다(공유자 기준, 수신자 수만큼 업로드).
- CPU: 6명 전원이 한 기기에서 디코딩 5개를 한다. CPU를 4배 느리게 한 모사(IT-30, 3명)에서도 연결·영상 진행이 유지됐다. **실제 저사양 기기는 미측정**.
- 장시간: 6명이 10분간 통화하는 시험(IT-29, `SOAK_MINUTES=10`)에서 20회 표본(30초 간격) 모두 모든 원격 영상이 진행하고 페이지 오류 0건(루프백·가상 영상). 20분 이상과 실제 네트워크는 **미측정**.
- **SFU 전환 검토 조건**(어느 하나가 반복되면): 실기기 6명 통화에서 품질이 받아들일 수 없음(UAT-06), 6명 초과 요구, TURN 릴레이 비율이 높아 비용 비정상, 모바일 발열·끊김 불만.

## 4. 한계 (미검증)
실제 네트워크 지연·손실, 저사양·모바일 기기, 장시간(20분 이상) 통화, 서버 CPU의 다중 코어 확장, TURN 서버 부하는 측정하지 못했다.
