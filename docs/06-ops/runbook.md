## 0. 지금 상태를 먼저 읽는다
- **배포된 환경이 없다.** 배포 대상(VM/PaaS)·도메인·TLS·예산은 사용자 결정 대기(U-02)다. 아래 명령은 Docker 기준이며 **로컬 컨테이너(호스트 네트워크)로 리허설한 것**이지 실서버에서 실행한 것이 아니다. `-p` 포트 매핑·브리지 네트워크·TLS 프록시·실도메인에서의 동작은 **미검증**이다.
- 판정(10단계, 2026-10-02): 내부·지인 시험은 조건부 가능, **불특정 다수 공개는 No-Go**(`release-checklist.md`). 남은 필수 사항: 알림 수신 채널 없음, 운영 TURN 구성 불가(TURNS·외부 IP), 09 이연 3건(엔진 연결 IP 상한, 빈 방 점유, TURN 자격 총량), 법률·연락처, 라이선스.
- 이 문서에서 **검증됨**은 "이 저장소 코드·컨테이너로 실제 실행해 확인"을 뜻한다. 검증 안 된 것은 그렇게 표시한다.

## 1. 시스템 개요
```
브라우저 ─ https/wss ─▶ [리버스 프록시: TLS 종단, WebSocket 허용] ─▶ MeetLite 서버 컨테이너(:3001)
                                                                   ├ REST(/api/*, /healthz) + Socket.IO(WebSocket 전용) + 웹 정적 파일
                                                                   └ admin 리스너(127.0.0.1:ADMIN_PORT, 선택, 컨테이너 안에서만 접근)
브라우저 ⇄ 브라우저 : 영상·음성·화면은 직접(WebRTC mesh, DTLS-SRTP). 직접 연결이 안 되면 coturn(TURN)이 중계
브라우저 → STUN(기본 공개 STUN stun.l.google.com) : 공인 주소 확인
```
- 컨테이너 1개(`Dockerfile`, Node 22, 비루트 `node`, 이미지 약 271MB)가 API·소켓·웹을 모두 제공한다(NFR-07). **방 상태는 프로세스 메모리뿐**이다(ADR-0002): DB·볼륨·마이그레이션이 없고, **재시작 = 진행 중인 모든 회의 종료**, 서버 인스턴스는 1개로 고정이다(수평 확장은 비목표).
- coturn은 별도 컨테이너/호스트(`infra/docker-compose.yml`, `network_mode: host`, 설정 `infra/coturn/turnserver.conf`)다. 앱 서버와는 `TURN_SECRET`(HMAC) 하나로만 이어진다.
- 한도 기본값: 방당 6명, 서버 방 100개, IP당 동시 연결 20, 끊김 유예 20초, 빈 방 10분 정리.
- 소켓은 **WebSocket만** 쓴다(롱폴링 폴백 없음, ADR-0006). 프록시가 WebSocket 업그레이드를 막으면 입장이 모두 실패한다.

## 2. 환경변수·시크릿 (이름과 관리 방법만. 값은 어떤 문서에도 쓰지 않는다)
전체 표(기본값·의미·바꾸면 생기는 일)는 `admin-manual.md` §2가 정본이다. 운영자가 반드시 알아야 할 것만 추린다.

| 이름 | 운영에서 | 비고 |
|---|---|---|
| `NODE_ENV` | **반드시 `production`** | 컨테이너 이미지는 이미 `production`이다. 이미지 밖(`npm start`)에서 빠뜨리면 예시 비밀값 거부 검사가 꺼진다(09 DEF-09-04, 10 E-06) |
| `ALLOWED_ORIGINS` | **필수** — 실제 `https://도메인`만(끝에 `/` 금지, `*` 금지) | 스테이징·로컬 값(`http://localhost…`)을 섞어 넣어도 **서버가 막지 않는다**(10 DEF-10-05). 배포 전 사람이 눈으로 확인한다 |
| `SESSION_SECRET` | **필수** — 32자 이상 난수, 예시값 거부 | 재시작·교체 사이에 **같게 유지**한다(바뀌면 참가자가 "서비스 재시작"이 아니라 "연결이 오래 끊겨 나갔습니다"를 본다, 08 OBS-S-02). 교체하면 모든 세션 무효 |
| `TRUST_PROXY` | 프록시 단계 수(보통 `1`) | 틀리면 전 이용자가 같은 IP로 보여 속도 제한·강퇴가 오동작한다 |
| `TURN_URLS`, `TURN_SECRET` | TURN을 쓸 때 **둘 다** | `TURN_SECRET`은 coturn과 같은 값. 예시값(`change-me…`) 거부 |
| `OPERATOR_CONTACT` | **공개 전 필수**(코드상 선택) | 이메일 또는 `https://` 주소. 비우면 처리방침·문의 화면이 "운영자가 아직 정하지 않았습니다"로 보이고 운영 기동 시 경고 로그가 난다 |
| `PRIVACY_OFFICER` | 지정 필요 여부는 법률 검토 후(**미확인**) | 비우면 화면에 "지정 전"으로 보인다 |
| `LEGAL_EFFECTIVE_DATE` | **공개 전 필수**(코드상 선택) | `YYYY-MM-DD`. 처리방침·약관은 법률 검토 전 **초안**이라 날짜를 정하기 전에 검토가 필요하다 |
| `ADMIN_PORT` + `ADMIN_TOKEN` | 방 폐쇄를 쓰려면 **둘 다**, 아니면 둘 다 비움 | 하나만 있으면 시작 실패 |
| `RATE_LIMIT_SCALE` | **설정하지 않는다**(기본 1) | 시험·부하용. 운영에서 1보다 크게 해도 서버가 거부하지 않아 속도 제한이 풀린다(10 DEF-10-05) |

**관리 방법**
- 시크릿(`SESSION_SECRET`, `TURN_SECRET`, `ADMIN_TOKEN`)과 설정은 **환경변수로만** 주입한다. 앱은 `.env` 파일을 읽지 않는다 — 컨테이너는 `docker run --env-file <파일>`, `npm start`는 환경변수가 이미 설정된 셸에서 실행한다(코드 확인, 10 E-18). 저장소에는 `.env.example`(예시, 비밀 아님)만 있다.
- 비밀값은 `openssl rand -base64 48` 같은 난수로 만든다. `ADMIN_TOKEN` 생성 명령은 `admin-manual.md` §4.
- **보관 위치(시크릿 매니저/볼트/서버의 접근 제한 파일 중 무엇을 쓸지)는 정해지지 않았다**(배포 대상 결정 대기). 정해지면 이 절에 "어디에 있는지"(경로·볼트 이름)만 적는다. 값은 이 저장소·문서·로그·메신저에 쓰지 않는다. 사고 시 교체 절차는 §9와 `incident-response.md`.
- 아래 §4의 "보관 대상" 때문에, 운영 `.env`(또는 동등한 시크릿 묶음)는 **백업이 있어야** 한다. 잃으면 `SESSION_SECRET`·`TURN_SECRET`을 새로 만들어야 하므로 모든 세션이 끊기고 coturn도 함께 바꿔야 한다.

## 3. 시작·중지
| 작업 | 명령 | 상태 |
|---|---|---|
| 시작(컨테이너) | `docker run -d --name meetlite --restart unless-stopped --env-file <.env 경로> --log-opt max-size=10m --log-opt max-file=3 -p 3001:3001 meetlite:<태그>` | 로컬 리허설은 `-p` 대신 `--network=host`로 실행·확인. **`-p 3001:3001`은 미검증**. admin 포트(`ADMIN_PORT`)는 **게시(`-p`)하지 않는다** |
| 시작(Node) | `npm ci && npm run build && npm start` (환경변수가 설정된 셸에서) | 검증됨 |
| 정상 종료 | `docker stop -t 15 meetlite` | 검증됨(유휴·응답하는 소켓은 0.1초대, 종료 코드 0) |
| 상태 확인 | `curl -sf https://<도메인>/healthz` → `{"status":"ok","uptimeSec":N}` | 검증됨 |
| 시작 실패 | `docker logs --tail 20 meetlite` 마지막 줄에 `환경변수 오류: <변수명>: <원인>` | 검증됨. 시작 실패 시 `restart` 정책 때문에 컨테이너가 **재시작 루프**에 빠진다(4초 만에 5회). 원인은 로그 마지막 줄 |

- **종료 시간·코드**: 응답 없는 클라이언트(네트워크가 끊긴 모바일 등)가 붙어 있으면 앱의 강제 종료 타이머 때문에 **정확히 10초 후 종료 코드 1**로 끝난다(`docker stop` 기본 대기도 10초라 코드 1과 137이 경합). 그래서 `-t 15`를 쓴다. **종료 코드 0·1·137은 모두 정상 범주로 본다**(10 E-17, DEF-10-06).
- **`--log-opt`**: 앱 컨테이너에 로그 로테이션을 주는 것은 이번 문서에서 추가한 권고다(coturn은 compose에 10m×3이 이미 있다). 옵션이 컨테이너에 적용되는 것까지만 확인했고 디스크 점유 추이는 미검증이다. 주지 않으면 Docker 기본 로그 드라이버는 크기 제한이 없다(일반 동작, 이번에 측정하지 않음).
- `restart: unless-stopped`가 없으면 프로세스가 죽었을 때 아무도 다시 띄우지 않는다. §3 첫 줄 명령에 넣었다.
- **재시작하면 모든 회의가 끝난다.** 이용자에게는 "서비스가 재시작되어 회의가 종료되었습니다"와 새 방 만들기가 보인다(08 IT-93 확인). 가능하면 이용이 적은 시간에 하고, 허용 시간대와 사전 공지 방식은 **사용자 결정 대기**(10 U-8)다. 무중단 배포·블루/그린은 설계상 불가능하다.

## 4. 보관 대상 (이것이 없으면 롤백·복구를 못 한다)
서버에는 백업할 **데이터가 없다**(DB·파일 쓰기 없음, 상태는 메모리). 대신 아래를 잃지 않는다.
| 보관 대상 | 왜 | 어디에 둘지 |
|---|---|---|
| 운영 `.env`(또는 동등한 시크릿·설정 묶음) 사본 | 새 서버로 옮기거나 롤백할 때 같은 `SESSION_SECRET`·`ALLOWED_ORIGINS`가 필요. 배포 직전 현재 것을 복사해 둔다 | **미정**(시크릿 보관 방식 결정 대기). 저장소에는 절대 두지 않는다 |
| **직전 정상 이미지 태그**(`docker images meetlite`) | 롤백(§5)이 이 이미지로 돌아간다. **`docker image prune`·`docker system prune`을 쓰지 않는다**(지우면 롤백 불가) | 서버 로컬. 레지스트리 사용 여부는 **미정**(10 U-7). 지웠다면 같은 커밋으로 다시 빌드한다(약 20초, 같은 커밋은 같은 앱 파일을 만든다 — 단 베이스 이미지가 부동 태그라 날짜에 따라 Node 패치 버전이 다를 수 있다) |
| **직전 정상 컨테이너**(`meetlite-prev`) | 가장 빠른 롤백(§5-A)은 이 컨테이너를 되살린다. 이전 환경변수·restart 정책이 그대로 복원된다 | 서버 로컬(정지 상태로 둠) |
| coturn 설정(`infra/coturn/turnserver.conf`, compose의 `TURN_REALM`)과 `TURN_SECRET` | coturn을 새로 올리거나 롤백할 때 필요. **coturn 롤백·교체는 실행해 보지 않았다(미검증)** | 설정 파일은 저장소, `TURN_SECRET`은 앱과 같은 시크릿 보관 위치 |
| 이미지 태그 규칙 | 롤백 대상을 알아보기 위해 | 권고: 배포 커밋 해시 앞 7자(`meetlite:<커밋>`). 이미지 빌드 `docker build -t meetlite:<커밋> .` |

## 5. 배포·롤백 (10단계가 로컬 컨테이너에서 실행으로 확인한 순서)
**전제**: 배포는 `npm run lint && npm run typecheck && npm test && npm run test:e2e`가 통과한 커밋만 한다(`release-checklist.md`). **GitHub Actions CI는 Docker 이미지를 빌드하지 않는다**(10 DEF-10-02) — Dockerfile이 깨져도 CI는 초록이므로 이미지는 배포 전에 직접 빌드해 확인한다.

### 5-1. 배포 전
1. 되돌아올 이미지가 있는지 본다: `docker images meetlite`. 현재 운영 태그를 적어 둔다.
2. 현재 운영 `.env`를 §4 위치에 사본으로 둔다. 새 릴리스가 **새 필수 환경변수**를 요구하면 이 `.env`에 먼저 추가하되 **옛 이미지도 그 `.env`로 떠야** 한다(롤백이 옛 `.env`+옛 이미지 쌍이면 가장 안전하다).
3. 이미지를 빌드한다: `docker build -t meetlite:<새태그> .` (베이스 이미지 다이제스트를 기록해 두면 재현에 도움이 된다. 배포 직전에 `trivy` 같은 스캔을 다시 돌리는 것을 권고 — 외부 이미지 취약점은 날짜에 따라 달라진다).
4. 이용자 공지·시간대를 확인한다(교체 순간 회의가 끊긴다).

### 5-2. 교체 (이름 충돌 없는 순서)
```
docker rm -f meetlite-prev          # 더 오래된 prev가 있으면 먼저 지운다(없으면 오류 메시지만 나오고 무시)
docker stop -t 15 meetlite          # 응답 없는 연결이 있으면 최대 10초
docker rename meetlite meetlite-prev   # 지우지 않고 이름만 바꿔 롤백용으로 둔다
docker run -d --name meetlite --restart unless-stopped --env-file <.env 경로> --log-opt max-size=10m --log-opt max-file=3 -p 3001:3001 meetlite:<새태그>
```
- 예전 문서(0.2)의 "같은 이름으로 새 컨테이너를 띄운다"는 `Conflict. The container name "/meetlite" is already in use`로 **실패한다**(10 R-02). 위 순서가 대안이다.
- **첫 줄을 빼먹으면** 두 번째 배포부터 `docker rename`이 `meetlite-prev` 이름 충돌로 실패한다. 이번 11단계 리허설에서 확인했다. 이때 `meetlite`는 이미 멈춘 상태이므로 `docker rm meetlite-prev` 후 `rename`부터 이어서 하면 된다.
- 첫 배포(교체할 컨테이너가 없음)는 §3의 시작 명령만 쓴다.

### 5-3. 판정 (사람이 한다 — 자동 감지·자동 롤백은 없다)
```
for i in 1 2 3 4 5 6; do curl -sf http://127.0.0.1:3001/healthz && break; sleep 5; done   # 30초 안에 ok
docker logs --tail 20 meetlite                                                          # '환경변수 오류'가 있으면 롤백
```
- **롤백 조건**: ① 30초 안에 `{"status":"ok"}`가 안 나온다 ② 로그에 `환경변수 오류`(재시작 루프) ③ 스모크 실패. Docker `HEALTHCHECK`는 30초 간격이고 `start-period`가 없어 `unhealthy`까지 몇 분 걸리며, 단일 컨테이너는 `unhealthy`에 반응하지 않는다(10 DEF-10-08). `docker ps`의 health 표시만 믿지 않는다.
- 스모크(검증된 요청 순서): ① `curl https://<도메인>/healthz` ② `curl -s -X POST -H 'Content-Type: application/json' -H 'Origin: https://<도메인>' -d '{"v":1}' https://<도메인>/api/rooms` → 201과 22자 `roomId` ③ `curl -s https://<도메인>/api/rooms/<roomId>` → `exists:true`. 이어서 **사람이** 브라우저 2개로 방에 입장해 서로 영상이 보이는지 확인한다(저장소에 대상 서버를 가리키는 스모크 스크립트는 없다, 10 DEF-10-09).

### 5-4. 롤백 (10단계에서 두 경로 모두 실행 확인, 이 11단계 리허설에서도 재확인)
**A. 빠른 길 — 직전 컨테이너 되살리기**
```
docker rm -f meetlite && docker rename meetlite-prev meetlite && docker start meetlite
```
이전 환경변수·restart 정책이 그대로 복원된다. 10단계 실측 약 0.6초, 11단계 리허설은 `healthz` 응답이 올 때까지 폴링해 약 0.64초(1회 측정).

**B. 이미지 길 — 직전 태그로 다시 실행**(`meetlite-prev`가 없을 때)
```
docker rm -f meetlite
docker run -d --name meetlite --restart unless-stopped --env-file <.env 경로> --log-opt max-size=10m --log-opt max-file=3 -p 3001:3001 meetlite:<직전태그>
```
직전 태그를 지웠다면 같은 커밋으로 다시 빌드한다.

**롤백 후**: 진행 중이던 회의는 **이미 끝났다**(메모리 휘발). 이용자 공지가 필요하다. 롤백한 뒤에는 다음 배포 전에 `docker rm -f meetlite-prev`(§5-2 첫 줄)가 필요하다. 새 릴리스가 새 환경변수를 요구하다 실패한 경우는 옛 `.env`+옛 이미지 쌍으로 롤백한다. 신·구 버전의 호환은 `api-spec.md` §10 참고.

**리허설 기록(2026-10-02, 로컬 컨테이너 `--network=host`, 증거는 `docs/harness/verify-log_11-documentation.md`)**: 현재 저장소를 `docker build`(약 23초) → 교체(stop→rename→run, 교체부터 `/healthz` ok까지 약 0.74초) → 합성 불량 릴리스 2종(`/healthz` 503, 시작 실패=재시작 루프) 교체 후 위 판정으로 실패 감지 → A(약 0.64초)·B(약 0.59초) 롤백 모두 `/healthz` ok로 복귀, `meetlite-prev`가 남은 채 다시 `rename`하면 이름 충돌로 실패함을 확인, 방 폐쇄(§6)를 `docker exec`로 실행 성공(200→404→401, 로그에 토큰 0회). 불량 릴리스는 현재 이미지 위에 CMD만 바꿔 만든 합성이다. **실환경(프록시·`-p`·실도메인), 레지스트리, 쿠버네티스/PaaS의 롤백 기능, coturn 롤백은 미검증이다.**

## 6. 방 폐쇄(신고 대응) 요약
신고된 방 **하나만** 서버 재시작 없이 닫는 절차다(POL-19). 서버 안에서만(`127.0.0.1`) 실행한다. **절차·확인·주의는 `admin-manual.md` §4가 정본이다.**
```
docker exec meetlite sh -c 'wget -qO- --header="Authorization: Bearer $ADMIN_TOKEN" --post-data="" http://127.0.0.1:$ADMIN_PORT/admin/rooms/<방ID>/close'
```
(작은따옴표 안의 `$ADMIN_TOKEN`·`$ADMIN_PORT`가 **컨테이너 안에서** 확장돼야 한다. 10단계에서 검증됨.)

## 7. 모니터링·알림
**현재 알림이 없다.** 알림 수신 채널(이메일·메신저·호출)이 정해져 있지 않고, 알림을 보낼 도구·MCP도 연결돼 있지 않다(10 §4.6, DEF-10-10). 정해진 것은 "운영자가 직접 본다"뿐이다.
| 볼 것 | 방법 | 정상 | 비정상 기준(`observability.md` §3의 제안, 배포 후 조정) |
|---|---|---|---|
| 서버 생존 | `curl -sf https://<도메인>/healthz` | 200 `{"status":"ok","uptimeSec":N}`, 보통 수 ms~수십 ms | 2분 이상 실패 → §8 |
| 재시작 여부 | `uptimeSec`가 작으면 최근 재시작(회의가 끊겼다는 뜻) | — | 예상 못 한 재시작 → 로그 확인 |
| 방·참가자 수 | `docker logs meetlite \| grep 'room created'`의 `rooms` 값(방 소멸 로그는 없어 **현재 방 수는 로그만으로 알 수 없다**) | 상한 `MAX_ROOMS`(기본 100) 미만 | 상한 도달 시 새 방 만들기가 503 |
| 메모리 | 호스트 도구(`docker stats meetlite` 등) | 시험 실측(루프백): 유휴 약 82MB, 6명 1방 피크 약 93MB, **100방×6명 시험에서 약 129MB**(TRD의 "100MB 미만" 가정은 초과) | 평소의 2배 이상 지속 → 방·소켓 수 확인 후 재시작 |
| 경로 비율(KPI-05) | `docker logs meetlite \| grep '"kpi":"path"'`를 `direct`/`relay`로 집계 | 관측용(목표 없음) | TURN 대역폭 비용과 연결 |
| 입장 거부·재접속 결과(KPI-01·04) | **로그가 없다 — 측정 불가**(08 DEF-S-01). `SERVER_BUSY` 증가 알람도 로그 이벤트가 없어 구현할 수 없다 | — | — |
| TURN | coturn 컨테이너 로그(10MB×3 로테이션). 수집·알림 설정 없음 | — | 트래픽 급증 → §8 |
| 인증서 만료 | 배포 대상 결정 후 정함 | — | 만료 14일 전 갱신(제안) |
- 대시보드는 **없다**(지표 수집기를 넣지 않은 것은 범위 통제 결정). 로그는 stdout JSON(pino)이며 수집·보관은 배포 대상(플랫폼)에 달려 있다. 로그에는 닉네임·IP·토큰·비밀번호·SDP·채팅이 **남지 않는다**(방 ID 앞 6자와 인원수만).
- 공개 전에는 **알림 수신 채널을 사용자가 정하고 테스트 알림을 한 번 발생시켜 수신을 확인**해야 한다(10 U-1). 내부 시험 단계라면 "운영자가 직접 `/healthz`를 본다"로 수용할지 사용자가 정한다.
- 알려진 로그 소음: 클라이언트 오류(400·413)도 `http error`(level 50)로 남는다. 개별 건은 공격이 아닐 수 있다.

## 12. 09단계 보안검증에서 운영자가 반드시 알아야 할 것
**수정 완료(9단계 후 반영, DEC-027)**: IPv6 /64 정규화로 비밀번호 시도·강퇴·방 생성 제한 우회 차단(DEF-09-01, High), 동시 오답이 5회 제한을 넘던 문제(DEF-09-03). 09 문서의 재판정(PASS)은 따로 기록되지 않았다(10 §1.1).

**열린 항목(공개 출시 전 필수 후보)**
| 항목 | 위험 | 운영자가 지금 할 수 있는 완화 |
|---|---|---|
| **앱 포트를 프록시 밖에 직접 노출 금지**(09 OBS-09-06) | `TRUST_PROXY`가 1 이상인데 앱 포트(3001)가 인터넷에 직접 열려 있으면 클라이언트가 `X-Forwarded-For`를 위조해 **모든 IP 기반 통제(속도 제한·비밀번호 시도·강퇴·연결 상한)를 우회**한다 | 앱 포트는 프록시(같은 호스트의 로컬 주소)에서만 접근 가능하게 방화벽/바인딩을 설정한다. 직접 노출(프록시 없음)이면 `TRUST_PROXY=0` |
| **엔진 연결 단계 IP 상한 없음**(09 DEF-09-02) | `IP_MAX_CONNECTIONS`는 Socket.IO 연결 완료 뒤에만 적용된다. 연결 패킷 없이 WebSocket만 여는 연결은 한 IP가 2000개까지 열렸다(RSS +44MB, fd 2022). 사실상 연결 폭주로 자원을 소진시킬 수 있다 | **프록시에서 IP당 동시 연결 제한(`limit_conn` 등)을 둔다.** 값은 `IP_MAX_CONNECTIONS`(20)보다 약간 넉넉하게. nginx 예시(**미검증**): `limit_conn_zone $binary_remote_addr zone=meetlite_conn:10m;` 후 `location`에 `limit_conn meetlite_conn 40;`. IPv6는 `$binary_remote_addr`가 전체 주소 단위라 /64 묶음이 안 된다. 프록시 종류는 미정 |
| 빈 방으로 방 수 상한 점유(09 DEF-09-05) | 한 IP가 방을 만들고 입장하지 않으면 `MAX_ROOMS`를 채워 다른 사람의 새 방 만들기가 503 | §8 `SERVER_BUSY` 행 |
| TURN 임시 자격 총량 무제한(09 DEF-09-06, **수용 여부 사용자 결정**) | 방을 만들 수 있는 누구나 TURN 자격을 받아 relay 대역폭·할당량을 소진할 수 있다. 정적 분석이며 실부하는 재현하지 않았다 | `TURN_TTL_SEC`를 줄이고 호스트 대역폭 알림을 둔다. 운영 TURN 구성(방식·비용 상한)은 사용자 결정(10 U-4) |
- **관찰·설계 한계**: 강퇴 우회는 IPv4를 바꾸면 가능(방 잠금이 유일한 완화, A-05) / 비호스트가 `screen:start`만 보내 화면공유 슬롯을 점유할 수 있고 호스트의 강제 해제는 없다(OBS-09-03) / 세션 토큰은 소지자 토큰(OBS-09-05) / 등록되지 않은 소켓 이벤트 연타는 위반 집계 대상이 아니다(OBS-09-02, 처리 비용 작음) / 처리방침 초안이 말하는 대로 속도 제한용 **IP 원문을 메모리에 최대 약 15분 보관**한다(디스크 저장 없음).
- Low 이연: `NODE_ENV` 미지정 시 예시 비밀값 허용(DEF-09-04), CI 액션 SHA 고정·Dependabot 없음(DEF-09-07 잔여), CSP의 미사용 Google 폰트 호스트(DEF-09-08), 보안 사건(비밀번호 차단·연결 종료)이 **로그에 남지 않음**(DEF-09-09 — 공격이 진행돼도 로그로는 알 수 없다).
- **미검증**: 실서버 응답 헤더·HTTPS·HSTS 실효, 실환경 admin 비노출(방화벽·프록시·포트 매핑), IPv6 실소켓, coturn IPv6 릴레이, 법령·STUN 약관 원문.
- 앱이 `Strict-Transport-Security: max-age=31536000; includeSubDomains`를 직접 보낸다. **같은 도메인의 다른 서브도메인이 HTTPS가 아니면 막힐 수 있다** — 도메인 선택 시 주의(미검증).
