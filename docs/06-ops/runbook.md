> 배포 대상이 정해지면(Phase 7, 사용자 결정) 명령을 그 환경에 맞게 갱신한다. 아래 명령은 Docker/Node 기준이다. 클라우드 시험 환경에서 이미지 빌드(271MB), 컨테이너 기동(`/healthz` 정상, 비루트 `node` 사용자, 예제 비밀값 거부, SIGTERM 즉시 종료·종료코드 0, HEALTHCHECK `healthy`)까지 확인했다(MC-03). **실제 서버·docker compose(coturn)에서는 실행해 보지 않았다.**

## 1. 시작·중지
| 작업 | 명령 |
|---|---|
| 시작(컨테이너) | `docker run -d --name meetlite --env-file .env -p 3001:3001 meetlite:<태그>` |
| 시작(Node) | `npm ci && npm run build && npm start` (환경변수는 `.env.example` 참고) |
| 정상 종료 | `SIGTERM`(docker stop). 새 연결을 막고 소켓을 닫은 뒤 종료, 10초 내 못 끝나면 강제 종료 |
| 상태 확인 | `curl https://<도메인>/healthz` → `{"status":"ok","uptimeSec":N}` |
| 시작 실패 | 로그에 `환경변수 오류:` 가 나오면 `.env`를 점검(필수: `ALLOWED_ORIGINS`, `SESSION_SECRET`) |

**중지·재시작하면 진행 중인 모든 회의가 끝난다**(메모리 상태, ADR-0002). 이용자에게는 "서비스가 재시작되어 회의가 종료되었습니다" 안내와 새 방 만들기가 보인다. 가능하면 이용이 적은 시간에 한다.

## 2. 배포·롤백
1. `npm run lint && npm run typecheck && npm test && npm run test:e2e`가 통과한 커밋만 배포한다(`release-checklist.md`).
2. 이미지를 빌드(`docker build -t meetlite:<태그> .`)하고 새 컨테이너로 교체한다(교체 순간 회의가 끊긴다).
3. `/healthz` 확인 → 방 만들기·입장 스모크(링크 열기, 2명 영상 확인).
4. **롤백**: 이전 태그 이미지로 다시 실행한다. 환경변수는 호환된다(상태 저장소가 없어 데이터 마이그레이션 없음).

## 4. 비밀값 교체
`SESSION_SECRET` 교체 → 서버 재시작 → 기존 세션·호스트 클레임 무효(진행 중 회의 종료). `TURN_SECRET`은 coturn과 서버를 **같은 값**으로 동시에 바꾼다. 교체 사유가 사고라면 `incident-response.md`.

## 6. 운영자 방 폐쇄 (POL-19)
신고(`/contact`로 받은 링크)된 방 **하나만** 서버 재시작 없이 닫는 절차다. 공개 포트와 별개인 **127.0.0.1 전용 admin 리스너**로만 동작하므로 서버에 SSH(또는 `docker exec`)로 들어가 서버 안에서 호출한다. 리버스 프록시에 이 포트를 연결하지 않는다.

**켜기**: `.env`에 `ADMIN_PORT`(예: 3002, `PORT`와 다른 값)와 `ADMIN_TOKEN`(32자 이상)을 **둘 다** 넣고 서버를 재시작한다. 하나만 있으면 서버가 시작되지 않고(`환경변수 오류`), 둘 다 없으면 리스너 자체가 없다(기본). 운영(`NODE_ENV=production`)에서 `change-me`로 시작하는 토큰은 거부된다. 켜지면 로그에 `admin listening (loopback)`이 한 줄 남는다.

**토큰 생성·교체**
```
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```
출력(43자)을 `.env`의 `ADMIN_TOKEN`에 넣고 재시작하면 교체된다(재시작하면 모든 회의가 끝나므로 이용이 적은 때에 한다). 토큰이 새었다고 의심되면 즉시 교체하거나 두 변수를 지우고 재시작해 끈다. 셸 기록에 남지 않게 `ADMIN_TOKEN`을 환경변수로 읽어 쓴다.

**닫기** — 신고된 링크가 `https://<도메인>/r/<방ID>`이면 `<방ID>`는 22자다.
```
curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:<ADMIN_PORT>/admin/rooms/<방ID>/close
```
| 응답 | 의미 |
|---|---|
| `200 {"closed":true,"participants":N}` | 닫힘. 참가자 전원에게 "운영자가 이 회의를 종료했습니다"가 보이고 소켓이 끊김(대기 중이던 방은 N=0) |
| `404 {"code":"ROOM_NOT_FOUND"}` | 이미 없거나 만료된 방(방 ID 오타 포함) |
| `401 {"code":"FORBIDDEN"}` | 토큰 없음·틀림(원인을 구분해 알려주지 않음) |
| `400 {"code":"INVALID_PAYLOAD"}` | 방 ID 형식 오류(22자 `A-Za-z0-9_-`) |
| `429 {"code":"RATE_LIMITED"}` | **틀린 토큰** 요청이 너무 잦음(순간 20회, 이후 초당 1회). 올바른 토큰의 요청은 이 한도에 걸리지 않으므로 운영자는 잠기지 않는다 |

**알아둘 것**
- 닫은 방의 ID는 다시 쓰이지 않는다(128비트 난수). 같은 링크로는 "회의를 찾을 수 없습니다"가 보이고, 이용자는 새 방을 만들 수 있다. 반복 남용자는 방 단위가 아니라 프록시/방화벽에서 IP를 차단한다(§3).
- **끊김 유예 중**(네트워크가 잠시 끊겨 재연결을 기다리던) 참가자는 소켓이 없어 "운영자가 종료" 안내를 받지 못하고, 돌아오면 "서비스가 재시작되어 회의가 종료되었습니다" 안내를 본다(방은 이미 닫힘).
- 기록: 로그에 `operator action`(방 ID 앞 6자와 인원수)만 남는다. 토큰·IP·전체 방 ID는 남기지 않으므로, **누가 언제 왜 닫았는지**는 운영자가 별도로 적는다(신고 접수 기록과 함께, 보유 기간은 신고 접수 내용과 같이 미정이며 사용자·법률 결정 사항이다).
- 방 목록 조회 기능은 없다(개인정보 노출 면적 최소화). 방 ID는 신고자가 준 링크에서만 얻는다.
- 위 명령은 개발 샌드박스에서 빌드한 서버(`node apps/server/dist/index.js`)에 `curl`로 실행해 `401`→`200`→`404`를 확인했다. **docker 컨테이너 안에서는 주의**: `node:22-alpine` 이미지에는 `curl`이 없고 `wget`만 있으며(실제 확인), `docker exec ... "$ADMIN_TOKEN"`처럼 쓰면 변수가 **호스트 셸에서** 확장된다. 컨테이너 안에서는 `docker exec -it <컨테이너> sh`로 들어간 뒤 그 안에서 토큰 값을 직접 넣어 `wget -qO- --header="Authorization: Bearer <토큰>" --post-data='' http://127.0.0.1:<ADMIN_PORT>/admin/rooms/<방ID>/close`처럼 호출한다(이 `wget` 형식은 실행 확인하지 않았다 — 미검증). 또한 `npm start`는 `.env` 파일을 읽지 않으므로(환경변수가 이미 설정된 셸에서 실행하거나 `docker run --env-file`을 쓴다) `.env`만 만들고 `npm start`를 하면 설정이 적용되지 않는다. 컨테이너 안에서 실제 배포 환경으로 실행해 본 적은 없다.
