## 1. 이 서비스에 "관리자 화면"은 없다
- 웹에는 관리자 화면·관리자 로그인·계정·역할 관리가 **없다**(회원가입/로그인은 비목표). 관리 기능은 **서버 안에서 실행하는 명령 한 가지(방 폐쇄)** 와 **환경변수 설정**뿐이다.
- 그래서 "관리자 권한"은 계정이 아니라 **서버에 들어갈 수 있는 사람이 `ADMIN_TOKEN`을 아는 것**이다. 토큰이 곧 권한이므로 §4의 보관·교체 규칙이 중요하다.

| 역할 | 어떻게 얻나 | 할 수 있는 일 | 할 수 없는 일 |
|---|---|---|---|
| 참가자 | 링크(+비밀번호)로 입장 | 마이크·카메라·채팅·화면공유(방당 1명) | 호스트·운영 기능 |
| 호스트 | 방을 만든 사람(탭 하나에서 한 번). 호스트가 나가면 가장 먼저 입장한 사람이 승계 | 자기 방 잠금·전체 음소거·내보내기. 서버가 방 상태로 확인한다 | 다른 방, 서버 설정 |
| **운영자(이 매뉴얼의 독자)** | 서버 셸 접근 + `ADMIN_TOKEN` | **방 하나를 즉시 닫기**, 설정 변경(재시작 필요), 로그 확인 | 방 목록 조회, 참가자 닉네임·IP 확인, 대화 열람, 개별 참가자 강퇴(호스트 기능), 화면공유 강제 해제 — 모두 **기능이 없다** |
| 시스템 소유자 | 서버·도메인·시크릿 관리 | 배포·롤백·시크릿 교체(`runbook.md`) | — |

- 방 폐쇄 기능은 인터넷에 열려 있지 않다. `127.0.0.1`에만 바인딩된 별도 포트이고(공개 포트의 `/admin/...`은 404, 로컬 확인), 프록시·방화벽에 연결하지 않는다. **실서버에서 외부 비노출은 미검증**이다.

## 3. 로그 보는 법
앱은 stdout에 JSON 한 줄씩(pino) 쓴다. 컨테이너라면 `docker logs meetlite`.
| `msg` | 필드 | 뜻 |
|---|---|---|
| `server listening` | `port`, `env` | 시작됨 |
| `admin listening (loopback)` | `adminPort` | 방 폐쇄 기능이 켜짐 |
| `OPERATOR_CONTACT 미설정…` (level 40) | — | 운영에서 연락처가 비어 있음 |
| `room created` | `room`(방 ID 앞 6자), `rooms`(현재 방 수) | 방 생성 |
| `participant joined` | `room`, `size`(방 인원) | 입장 |
| `peer path` | `kpi:"path"`, `path`(`direct`/`relay`) | 연결 경로(TURN 사용 비율 집계용). 방·사람 식별 정보 없음 |
| `operator action` | `action`: `close`(`room` 앞 6자, `size`) / `auth-failed` (level 40) | 방 폐쇄 / admin 인증 실패 |
| `http error`, `handler error` | `status` 또는 `event`, `type`(오류 이름) | 오류. 400·413도 level 50으로 남는다(소음) |
| `shutting down` | `signal` | 종료 중 |

- **남지 않는 것**: 닉네임, IP, 세션 토큰, 비밀번호, SDP·ICE, 채팅 본문, 전체 방 ID, `ADMIN_TOKEN`(토큰 문자열이 로그에 0회임을 확인). 따라서 로그만으로 **누가** 그 방에 있었는지는 알 수 없다.
- **신고 링크 ↔ 로그**: 신고 링크의 방 ID 앞 6자로 `room created`·`operator action` 줄을 찾을 수 있다(앞 6자는 입장에 불충분하다는 판단으로 남긴다, DEC-020).
- **방이 사라질 때의 로그는 없다.** 현재 방 수를 알려면 `room created`의 `rooms`를 보되 방이 끝나도 줄지 않는다.
- **로그에 없는 것(알아야 할 공백)**: 입장 거부(비밀번호 오답 차단·잠금·정원), 위반 누적에 의한 연결 종료, IP 상한 거부, 재접속 결과. 공격이 진행돼도 로그로는 보이지 않는다(08 DEF-S-01, 09 DEF-09-09).
- TURN 로그는 coturn 컨테이너 쪽이며 **접속 IP와 사용자명이 남을 수 있다**(처리방침 초안이 이를 밝힌다). 보관은 10MB×3 로테이션이다.

## 4. 방 폐쇄 (되돌릴 수 없는 작업)
신고된 방 **하나만** 서버 재시작 없이 닫는다(POL-19).

### 4-1. 켜기·끄기
`ADMIN_PORT`(예: `PORT`와 다른 번호)와 `ADMIN_TOKEN`을 **둘 다** 설정하고 재시작한다. 켜지면 로그에 `admin listening (loopback)` 한 줄이 남는다. 둘 다 없으면 리스너 자체가 없다(기본). 컨테이너의 **admin 포트는 `-p`로 게시하지 않는다**(게시해도 127.0.0.1 바인딩이라 접근은 안 되지만 불필요).

토큰 생성(출력은 43자, 실행해 확인함):
```
node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"
```
출력을 시크릿 보관 위치의 `ADMIN_TOKEN`에 넣는다(보관 위치는 미정, `runbook.md` §2). 셸 기록에 남지 않게 값을 명령행에 직접 쓰지 않고 환경변수로 읽어 쓴다. **교체**: 새 값을 넣고 재시작(모든 회의가 끝난다 — 이용이 적은 때). 유출이 의심되면 즉시 교체하거나 두 변수를 지우고 재시작해 기능을 끈다.

### 4-2. 닫기 전에 반드시 확인 (되돌릴 수 없다)
방을 닫으면 **참가자 전원이 즉시 쫓겨나고 방은 영구 삭제**된다(같은 링크는 다시 쓸 수 없고 방 ID는 재사용되지 않는다). 복구·실행 취소가 없다. 아래를 모두 확인한 뒤 실행한다.
1. [ ] **신고 접수 기록이 있다**: 누가, 언제, 어떤 링크로, 무슨 문제를 신고했는지 운영자가 **따로** 적었다(서버는 사유·시각·집행자를 기록하지 않는다).
2. [ ] **방 ID가 정확하다**: 신고된 링크가 `https://<도메인>/r/<방ID>` 꼴이고 `<방ID>`가 22자(`A-Za-z0-9_-`)다. 복사 오류로 다른 방을 닫으면 되돌릴 수 없다. 신고자가 준 링크 문자열을 그대로 쓰고 앞 6자를 로그의 `room created`와 대조해 본다.
3. [ ] **닫을 필요가 있다**: 호스트가 직접 해결할 수 있는 문제(참가자 내보내기·방 잠그기)인지 먼저 생각한다. 폐쇄는 무고한 참가자의 회의도 끝낸다.
4. [ ] **토큰을 안전하게 쓴다**: 변수로 읽어 쓰고 명령행·티켓·메신저에 값을 붙이지 않는다.

### 4-3. 실행 (실행해서 확인함: 2026-10-02, 컨테이너 안 `docker exec`)
```
docker exec meetlite sh -c 'wget -qO- --header="Authorization: Bearer $ADMIN_TOKEN" --post-data="" http://127.0.0.1:$ADMIN_PORT/admin/rooms/<방ID>/close'
```
- **작은따옴표 필수**: `$ADMIN_TOKEN`·`$ADMIN_PORT`가 컨테이너 안 셸에서 확장돼야 한다. 큰따옴표로 바깥에서 감싸면 호스트 셸이 변수를 확장해 빈 토큰이 되어 `401`이 난다(실제 확인). `node:22-alpine`에는 `curl`이 없고 `wget`(busybox)만 있다.
- 컨테이너가 아닌 Node 직접 실행이라면 같은 서버 안에서: `curl -s -X POST -H "Authorization: Bearer $ADMIN_TOKEN" http://127.0.0.1:<ADMIN_PORT>/admin/rooms/<방ID>/close`(검증됨).
- `npm start`는 `.env` 파일을 읽지 않는다. `.env`만 만들고 실행하면 설정이 적용되지 않는다.

| 결과 | 의미 |
|---|---|
| `{"closed":true,"participants":N}` (wget 종료 코드 0) | 닫힘. 참가자 전원에게 "운영자가 이 회의를 종료했습니다"가 보이고 연결이 끊김(대기 중이던 방은 N=0) |
| wget이 `server returned error: HTTP/1.1 404 Not Found` | 방이 없음(이미 끝났거나 방 ID 오타). **이 경우 방 ID를 다시 확인한다.** busybox `wget`은 오류 본문을 보여 주지 않는다 |
| `HTTP/1.1 401 Unauthorized` | 토큰이 없거나 틀림(원인 구분 없음). 변수 확장 위치(작은따옴표)와 `ADMIN_TOKEN` 값을 확인 |
| `400` / `405` / `413` | 방 ID 형식 오류 / 잘못된 메서드·경로 / 본문 1KB 초과 |
| `429` | **틀린 토큰** 요청이 잦음(순간 20회, 이후 초당 1회). 올바른 토큰은 이 한도에 걸리지 않아 운영자는 잠기지 않는다 |
| `500` | 서버 내부 오류. 로그 `admin handler error`를 확인 |
오류 상태를 보고 싶으면 `wget -S -O-`로 응답 상태 줄을 확인한다(검증됨). 인증 실패는 로그에 `operator action {action:"auth-failed"}`(level 40)로 남는다.

### 4-4. 닫은 뒤
- 로그에 `operator action {action:"close", room:<앞 6자>, size:N}`이 한 줄 남는다. 이것이 서버가 남기는 **유일한 기록**이므로, **누가 언제 왜 닫았는지**는 운영자가 신고 접수 기록에 적는다. 신고 기록의 보관 기간은 정해지지 않았다(사용자·법률 결정, **미정**).
- 닫힌 방의 링크는 "회의를 찾을 수 없습니다"가 보이고 이용자는 새 방을 만들 수 있다. 같은 사람이 새 방을 만드는 것은 막지 못한다 — 반복 남용자는 **방 단위가 아니라 프록시/방화벽에서 IP를 차단**한다(`runbook.md` §8).
- **끊김 유예 중**(네트워크가 잠시 끊겨 20초 안에 돌아오기를 기다리던) 참가자는 안내를 못 받고, 돌아오면 "서비스가 재시작되어 회의가 종료되었습니다"를 본다(방은 이미 닫힘).
- **방 목록 조회·검색 기능은 없다**(개인정보 노출 최소화). 방 ID는 신고자의 링크에서만 얻는다.

## 5. 신고를 받았을 때 (흐름)
1. 신고는 문의·신고 화면(`/contact`)의 연락처(`OPERATOR_CONTACT`)로 들어온다. 이 값이 비어 있으면 신고 창구가 없는 것이다(공개 전 필수).
2. 신고자에게 링크·일시·내용을 요청한다(**방 비밀번호는 받지 않는다**).
3. 호스트가 해결할 수 있는지 확인한 뒤(§4-2-3), 필요하면 방 폐쇄(§4).
4. 같은 사람이 반복하면 프록시에서 IP 차단. 앱은 IP 원문을 기록하지 않으므로 **프록시 로그**가 근거다(배포 대상 결정 후).
5. 신고 처리 **기한**과 **수사 협조 요청 응대**는 정해지지 않았다(미정, 법률 검토 필요). 화면은 "처리 기한은 운영자가 정해 안내합니다(미정)"라고 말한다.
6. 보안 취약점 제보는 `SECURITY.md`(연락처 미정)로 받도록 되어 있다. 사고 판단은 `incident-response.md`.

## 6. 알려진 한계 (운영자가 이용자 문의에 답하기 위해)
| 한계 | 내용 |
|---|---|
| 재시작 = 회의 종료 | 방은 서버 메모리에만 있다. 재시작·롤백·시크릿 교체·설정 변경은 모두 진행 중인 회의를 끝낸다 |
| 강퇴 차단의 오차단·우회 | 강퇴는 세션+IP 해시(방이 있는 동안)로 막는다. **같은 공인 IP(가정·사무실 NAT)의 다른 사람과 호스트 본인까지 재입장이 막힐 수 있다.** IPv6는 /64 단위라 같은 /64의 사용자도 함께 막힌다. 반대로 다른 네트워크(모바일 데이터·VPN)로 옮기면 우회된다. 방 잠금이 유일한 보완이다 |
| 방 단위 신고 처리의 한계 | 폐쇄한 사람이 새 방을 만드는 것을 앱은 막지 못한다 |
| 화면공유 슬롯 점유 | 비호스트가 `screen:start`만 보내고 공유하지 않아도 슬롯을 잡을 수 있고, 호스트의 강제 해제는 없다(내보내기만 가능) |
| IP 상한 | `IP_MAX_CONNECTIONS`는 연결 완료 뒤에만 적용 → 프록시 `limit_conn` 필요(`runbook.md` §12) |
| 빈 방 점유·TURN 자격 총량 | 09 DEF-09-05·06, 열린 상태 |
| 모바일 | 화면공유 불가, iOS Safari 실기기 **미검증**, 화면이 꺼지면 통화가 멈출 수 있음 |
| 법률 | 처리방침·약관은 초안, 개인정보 법령·국외 이전·STUN 약관 **미확인** |

## 7. 장애 대응
증상별 표는 `runbook.md` §8이 정본이다. 가장 먼저 할 것:
1. `curl -sf https://<도메인>/healthz` (또는 `http://127.0.0.1:<PORT>/healthz`).
2. `docker ps -a`, `docker logs --tail 20 meetlite` — 마지막 줄에 `환경변수 오류`가 있으면 설정 문제다.
