## 1. 범위와 전제
로그인이 없는 익명 서비스다. **128비트 방 ID를 아는 것이 입장 권한**이고 선택적 비밀번호·잠금·호스트 대기·강퇴가 그 위에서 보완한다. 미디어는 브라우저 간 P2P(DTLS-SRTP)이며 서버는 미디어를 보지 못한다. 서버는 시그널링·방 상태(메모리)만 갖는다. 운영은 HTTPS/WSS를 전제한다.

## 2. 신뢰 경계
| 경계 | 신뢰 | 검증 |
|---|---|---|
| 브라우저 → 서버(HTTP·소켓) | **신뢰하지 않음**: 모든 입력은 zod strict 검증, 크기·속도 제한 | TC-31, 40, 43, 80, 81, 105 |
| 서버 내부 상태 | 신뢰 | 권한은 항상 서버 상태로 판단(UI 숨김 아님) TC-18, 20, 60 |
| 참가자 ↔ 참가자 | 미디어는 직접 연결(IP 노출 가능) | 대기실 고지 UX-09, IT-26 |
| 서버 ↔ coturn | 공유 비밀(HMAC)로만 연결 | IT-21, 22 |

## 3. 자산
회의 내용(음성·영상·화면·채팅) · 방 접근 권한(방 ID, 비밀번호) · 참가자 신원(닉네임, IP·SDP에 포함된 네트워크 정보) · TURN 릴레이 대역폭(비용) · 서비스 가용성 · 비밀값(`SESSION_SECRET`, `TURN_SECRET`).

## 4. 공격자
외부 익명(링크·ID 추측, 대량 요청, 임의 소켓 클라이언트) · 악의적 참가자(사칭, 스팸, XSS, 강퇴 우회, 타 방 조작) · 링크 유출자 · 네트워크 중간자(HTTPS 미적용 시) · 리소스 남용자(TURN 무료 프록시).

## 6. 남은 위험 (수용 또는 후속)
1. **링크 유출 = 입장 가능**(비밀번호 없는 방). 잠금·강퇴·호스트 대기·비밀번호로 완화. 계정이 없는 설계의 한계.
2. **강퇴 우회**: 차단 키는 세션+IP 해시(서버 메모리). 다른 네트워크로 옮기면 재입장 가능. 방 잠금으로 보완. (A-05, 개인정보는 IP 원문 미저장)
3. **mesh에서 참가자 간 IP 노출**(T10). 릴레이 강제는 비용·지연 증가라 보류.
4. **분산 DoS**는 앱 계층만으로 불가 → 앞단 프록시/CDN 필요(배포 시).
5. **TURN 자격증명은 TTL 내 재사용 가능**. TTL 1시간·할당량으로 한도 제한.
6. **채팅은 종단간 암호화가 아니다**. TLS 구간에서 서버를 지나며 저장·로그하지 않는다.
7. **HTTP 단독 배포 불가**(브라우저가 미디어 권한 거부). 리버스 프록시/TLS가 필수.
8. **미검증**: 외부 침투 시험, 비-Chromium 브라우저에서의 보안 헤더 동작, 실제 운영 coturn 하드닝 값, 대규모 트래픽.
