## 3. 대응 절차
1. **격리**: 서버 중지/재시작(방은 사라진다). 트래픽 급증 시 프록시에서 차단.
2. **비밀값 교체**: `SESSION_SECRET` 교체 → 모든 세션·클레임 토큰이 무효가 된다. `TURN_SECRET`은 서버와 coturn을 함께 교체.
3. **의존성**: `npm audit`, 패치 후 재배포.
4. **로그 확인**: 구조화 로그에서 시간대·이벤트 코드만 확인(개인정보 없음). 필요하면 프록시 로그의 IP로 차단.
5. **통지**: 영향받는 이용자가 있고 개인정보가 관련되면 법령에 따른 통지 의무를 확인한다(**미확인**, U-04).
6. **사후 분석**: 원인, 영향, 재발 방지를 `defects.md` 또는 별도 기록에 남기고 `security.md`·점검표를 갱신한다.

## 4. 취약점 신고 안내
루트 `SECURITY.md`에 신고 방법을 둔다(연락처는 운영자가 U-03에서 정해 채운다).
