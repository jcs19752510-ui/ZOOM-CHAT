## 1. 페르소나 (상세는 `personas-journeys.md`)
- **P1 호스트 지은(34, 스터디 운영)**: 링크를 만들어 공유하고 모임을 진행. 기술에 익숙하지 않음.
- **P2 참가자 영숙(62, 모바일 Safari)**: 링크를 눌러 들어오기만 하길 원함. 설치·가입 거부감이 큼.
- **P3 운영자 찬성(개발자, 1인 운영)**: 비용·장애·악용을 혼자 감당. 단순한 구조와 로그가 필요.

## 2. 우선순위 기준 (MoSCoW)
**M**(Must: 없으면 출시 불가) / **S**(Should: 출시 목표, 일정 시 후순위 가능) / **C**(Could) / **W**(Won't: 비목표). 요구 ID는 삭제하지 않고 상태만 바꾼다.

## 7. 보안 요구 (SEC) — 요약, 상세와 대응은 `04-security/security.md`(Gate 0-D)
| ID | 요구 요약 |
|---|---|
| SEC-01 | 방 ID는 crypto 기반 128비트 이상 난수(URL-safe). |
| SEC-02 | 방 비밀번호는 해시로만 보관, 입장 시도를 IP+방 기준 제한. |
| SEC-03 | 입장 시 서명된 단기 세션 토큰 발급, 이후 모든 소켓 이벤트·재접속을 토큰으로 검증. |
| SEC-04 | 발신자 ID는 서버 부여값만 신뢰(사칭 방지), 같은 방 참가자에게만 릴레이. |
| SEC-05 | 호스트 여부·모든 권한은 서버 상태로만 판단, 강퇴 세션 재입장 차단. |
| SEC-06 | 모든 소켓 이벤트에 zod 검증·크기 제한·이벤트별 rate limit, IP당 동시 연결 수와 서버 전체 방 수 상한. |
| SEC-07 | 채팅 길이 제한, 텍스트로만 렌더링, 링크 `rel="noopener noreferrer"`. |
| SEC-08 | Origin 허용 목록(CORS+Socket.IO), CSP, Permissions-Policy, HTTPS 전제, 오류에 내부 정보 미노출. |
| SEC-09 | TURN 단기 HMAC 임시 자격증명, 고정 비밀번호 금지, 사설/루프백 릴레이 차단, 할당량. |
| SEC-10 | 비밀값은 `.env`만, 로그에 개인정보·SDP·토큰 미기록. |
| SEC-11 | 공급망: `npm ci` + lockfile, 새 의존성은 사전 보고, `npm audit`. |
